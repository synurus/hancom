# 코드북 — 유저 시나리오

## 페르소나

**이현우** — 파트 C(게임 화면) 담당. 3주차 발표에서 "코드를 이해할 수 있는가?" 질문이 자기 파트 밖(백엔드 상태 관리)으로 올 수도 있다는 걸 알고 있음. PR diff는 꾸준히 봐왔지만, 그 파일이 게임 전체에서 어떤 역할을 하는지는 자신 있게 설명하기 어려운 상태.

## 상황

발표 전, 예전부터 궁금했던 `apps/backend/src/view.ts`를 제대로 이해하고 넘어가고 싶음. 파일 자체는 97줄이라 짧지만, 왜 그렇게 짜여 있는지(설계원칙·과거 사건)는 코드만 봐선 안 보임.

## 시나리오

1. 디스코드 `#code-book` 채널 핀 메시지에서 파일트리.md("메뉴판")를 열어 어떤 파일들이 있는지 훑어봄
2. 궁금했던 경로를 채팅에 그대로 적음: `apps/backend/src/view.ts`
3. 김정현이 요청을 모아 `/codebook` 스킬 실행 — 스킬이 먼저 설계원칙·파트 분담·과거 사건 6건 같은 배경지식을 채우고, 그 위에서 실제 코드를 읽어 분기형 문서를 씀
4. 결과가 `TeamB` 저장소 `3주차/코드북/view.md`로 커밋되고, 링크가 채널에 공유됨
5. 현우가 링크를 열어 1번 노드부터 읽기 시작 — "같은 방인데 사람마다 다른 화면을 받는다는 걸 이미 아신다" 질문에 "아니오"를 골라 2번(`RoomInternalState` vs `GameState`)부터 순서대로 읽음. 아는 사람이었다면 6번으로 바로 건너뛸 수도 있었음
6. 8번 노드(`isPostGame`·`myPhase`)에서 "설계원칙 5"라는 말이 왜 나오는지 헷갈림 — `#code-book`에 "8번 이해 안 됨"이라고 남김
7. 김정현이 해당 노드만 더 쪼갠 버전으로 다시 올림 — 처음 것보다 짧은 설명 단위로 나뉘어 이번엔 이해됨
8. 마지막 14번(도착) 노드까지 다 읽고, 채널에 한 줄 남김: "이제 `view.ts`가 왜 유일한 상태 출구인지 설명할 수 있습니다"

## 얻는 것

- diff만으로는 안 보이던 "이 파일이 전체 흐름의 어디에 있는가"를 남의 파트 코드로도 이해하게 됨
- 이해 안 되는 지점을 "몇 번 노드"로 콕 짚어 되돌려줄 수 있어서, 막연히 "모르겠다"보다 개선이 빠름
- "이제 설명할 수 있습니다"라는 한 줄이 — 문서 자체는 AI가 썼더라도 — 사람이 실제로 이해했다는 증거로 채널에 남음
- 한 번 요청 흐름을 겪어보면, 다음에 다른 파일(`stateMachine.ts` 등)을 요청할 때도 같은 절차를 그대로 반복 가능
