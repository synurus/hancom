# 2026-08-04 CSS 코드 분석 — `width: 100%`인데 왜 박스가 삐져나올까?

> 대상 파일: `260804_code_review_Q.css` (2주차 · CSS)

---

## 정답 요약

| 질문 | 답 |
|---|---|
| **Q1.** A와 B 중 컨테이너에 딱 맞는 쪽은? | **B** (`box-sizing: border-box`가 있는 쪽) |
| **Q2.** 왜 한쪽은 넘칠까? | A는 기본값 `content-box`라서 `width: 100%`(=400px)가 **콘텐츠 영역만**의 크기이고, 좌우 `padding` 40px가 그 **바깥에 추가로** 붙어 총 440px가 되기 때문 |

---

## 1. 문제의 핵심: `box-sizing`

CSS에서 `width`가 "무엇의 폭"을 가리키는지는 `box-sizing` 값에 따라 달라집니다.

```
box-sizing: content-box  (기본값)
  width = 콘텐츠 영역만
  실제 차지하는 폭 = width + padding-left/right + border-left/right

box-sizing: border-box
  width = 콘텐츠 + padding + border 를 모두 포함한 값
  실제 차지하는 폭 = width (그대로)
```

`box-sizing`을 적지 않으면 **`content-box`가 기본값**입니다. 이게 A 코드가 넘치는 이유입니다.

---

## 2. A 코드 계산

```css
.card {
  width: 100%;
  padding: 20px;
}
```

1. `.wrap`의 콘텐츠 폭이 400px이므로 `width: 100%` → **400px**
2. `box-sizing`이 없으니 기본값 `content-box` → 이 400px는 **콘텐츠 영역만**의 폭
3. 여기에 `padding: 20px`의 좌우 40px가 **바깥으로 추가**

```
실제 폭 = 400 (콘텐츠) + 20 (왼쪽 패딩) + 20 (오른쪽 패딩) = 440px
```

`.wrap`은 400px이므로 → **오른쪽으로 40px 넘침** ❌

```
|<---------------- .wrap 400px ---------------->|
|<------------------ .card 440px -------------------->|
                                                 ↑ 40px 삐져나옴
```

---

## 3. B 코드 계산

```css
.card {
  width: 100%;
  padding: 20px;
  box-sizing: border-box;
}
```

1. `width: 100%` → **400px**
2. `border-box`이므로 이 400px 안에 padding이 **포함**됨
3. 브라우저가 콘텐츠 영역을 역산

```
콘텐츠 폭 = 400 - 20 - 20 = 360px
실제 폭   = 400px  ✅ 딱 맞음
```

```
|<---------------- .wrap 400px ---------------->|
|<---------------- .card 400px ---------------->|
| 20px |<----- 콘텐츠 360px ----->| 20px |
```

---

## 4. 왜 헷갈리기 쉬운가

- **`width: 100%`의 기준은 부모의 "콘텐츠 폭"**입니다. `.wrap`은 `width: 400px`에 `border: 2px`가 있지만, `.wrap` 자체도 기본 `content-box`라 콘텐츠 폭은 그대로 400px입니다. (border 4px는 바깥으로 붙어 `.wrap`의 실제 폭이 404px가 됩니다.)
- 즉 `100%`는 "부모가 화면에서 차지하는 크기"가 아니라 **"부모의 콘텐츠 영역 크기"**입니다.
- `height`도 동일한 규칙이 적용됩니다. 세로 방향 padding으로 인한 넘침도 같은 원리입니다.

---

## 5. 주의: `margin`은 `border-box`에 포함되지 않는다

`border-box`가 포함하는 것은 **content + padding + border**까지입니다. **margin은 포함되지 않습니다.**

```css
.card {
  width: 100%;
  padding: 20px;
  margin: 0 10px;      /* ← 좌우 20px 추가 → 다시 넘침! */
  box-sizing: border-box;
}
```

margin까지 감안해야 한다면 `calc()`를 쓰거나, 애초에 `width`를 지우는 편이 낫습니다 (아래 참고).

---

## 6. 실무 권장 패턴

### (1) 전역 리셋 — 가장 일반적

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

프로젝트 시작 시 이 3줄을 넣어두면 A 코드 같은 실수 자체가 사라집니다. 대부분의 CSS 리셋/프레임워크(Bootstrap, Tailwind 등)가 기본으로 적용합니다.

### (2) 더 나은 대안 — `width`를 아예 지우기

`div` 같은 블록 요소는 기본적으로 부모 폭을 꽉 채우되, padding/border가 있으면 **콘텐츠를 줄여서 알아서 맞춥니다.**

```css
.card {
  /* width 선언 없음 */
  padding: 20px;
}
```

이렇게만 해도 결과는 B와 동일하게 400px에 딱 맞습니다. `width: 100%`는 블록 요소에서 대부분 불필요하며, 오히려 이번 같은 버그를 만듭니다.

> 다만 `display: inline-block`, `position: absolute`, flex 아이템 등 폭이 자동으로 늘어나지 않는 경우에는 `width: 100%`가 필요할 수 있습니다.

---

## 7. 검증 방법

브라우저 개발자도구(F12)에서 `.card`를 선택하면 **Computed → Box Model** 다이어그램으로 실제 수치를 확인할 수 있습니다.

- A: content `400`, padding `20`, 전체 440
- B: content `360`, padding `20`, 전체 400

또는 콘솔에서:

```js
document.querySelector('.card').getBoundingClientRect().width
// A → 440,  B → 400
```

---

## 8. 코드 자체에 대한 참고

원본 파일은 A/B를 한 파일에 나란히 두었기 때문에, 그대로 브라우저에서 열면 **동일한 `.card` 선택자가 3번 중복 선언**되어 나중 규칙이 우선 적용됩니다. 실제 결과는 마지막에 오는 B + 공통 설정이 합쳐진 상태가 됩니다.

**확인할 때는 A 또는 B 중 한 블록만 남기고 나머지는 주석 처리**해야 의도한 비교가 됩니다.

---

## 한 줄 정리

> `width: 100%` + `padding`은 기본값 `content-box`에서 **반드시 넘친다.**
> `box-sizing: border-box`를 쓰거나, 블록 요소라면 `width` 선언을 지우면 해결된다.
