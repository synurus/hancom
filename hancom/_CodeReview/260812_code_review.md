# 코드 리뷰: `260812_code_review_Q.js`

**대상 파일**: `260812_code_review_Q.js`
**주제**: 쇼핑몰 가격 필터 — 상품 가격을 "낮은 가격순"으로 정렬

## 요약

이 코드는 배열을 "낮은 가격순"으로 정렬하려는 의도이지만, `Array.prototype.sort()`를 비교 함수 없이 호출하고 있어 **숫자 정렬이 아닌 문자열(사전식) 정렬**이 일어난다. 이 자체가 학습 목적의 질문(퀴즈)이라면 의도된 함정으로 보이지만, 실제 프로덕션 코드라면 반드시 고쳐야 할 버그다.

## 이슈

### 1. (Critical) `sort()`에 비교 함수가 없어 문자열 기준으로 정렬됨

```js
prices.sort();
```

`Array.prototype.sort()`는 비교 함수를 넘기지 않으면 각 요소를 **문자열로 변환한 뒤 유니코드 코드 포인트 순서**로 비교한다. 숫자 배열이라도 예외가 아니다.

`[12000, 900, 45000, 3500]`을 문자열로 보면 `"12000"`, `"900"`, `"45000"`, `"3500"`이고, 첫 글자부터 비교하면:

- `"1..."` < `"3..."` < `"4..."` < `"9..."`

따라서 실행 결과는 기대했던 `[900, 3500, 12000, 45000]`이 아니라 다음과 같이 나온다.

```
낮은 가격순: [ 12000, 3500, 45000, 900 ]
```

**원인 코드**: 14번째 줄 `prices.sort();`

**수정안**: 숫자를 오름차순으로 비교하는 콜백을 명시적으로 전달한다.

```js
prices.sort((a, b) => a - b);
```

### 2. (Minor) `sort()`는 원본 배열을 그대로 변형(mutate)함

`sort()`는 새 배열을 반환하지 않고 원본 배열을 제자리에서 정렬한다. 이 스크립트에서는 `prices`를 이후에 다시 쓰지 않으므로 당장 문제는 없지만, 원본 배열의 순서를 보존해야 하는 상황이라면 예상치 못한 부작용이 될 수 있다.

```js
// 원본을 보존하고 싶다면
const sortedPrices = [...prices].sort((a, b) => a - b);
// 또는 ES2023+
const sortedPrices = prices.toSorted((a, b) => a - b);
```

## 결론

- 핵심 문제는 14번째 줄 한 곳: `prices.sort()` → `prices.sort((a, b) => a - b)`로 수정하면 의도한 "낮은 가격순" 정렬이 정상 동작한다.
- 이 파일이 학습용 퀴즈라면(파일 상단 주석의 Q1/Q2), 위 원인 분석이 그대로 모범답안 역할을 할 수 있다: **Q1(예상과 다른 부분)** = 900이 맨 뒤로 밀려나는 등 숫자 크기와 무관하게 정렬됨, **Q2(원인)** = `sort()`가 비교 함수 없이 문자열 비교를 수행하기 때문(14번째 줄).
