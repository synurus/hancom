# CSS 중앙 정렬 비교 분석 — A(absolute+transform) vs B(flexbox)

원본 파일: `260805_code_review_Q.css` (2주차 CSS 학습 문제)

## 문제 요약

`.box`를 `.wrap` 한가운데 배치하는 두 가지 방법을 비교합니다. 렌더링 결과는 동일합니다.

**A 코드**
```css
.wrap { position: relative; }
.box  { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }
```

**B 코드**
```css
.wrap { display: flex; justify-content: center; align-items: center; }
```

## Q1. 유지보수·견고성 면에서 어느 쪽이 나을까?

**B(flexbox)가 더 낫습니다.**

## Q2. 왜 그럴까?

### 1. 문서 흐름(document flow) 처리 방식이 다르다

- **A**: `.box`를 `position: absolute`로 문서 흐름에서 완전히 빼냅니다. `.wrap`에 형제 요소가 하나라도 추가되면, 그 형제는 `.box`가 존재하지 않는 것처럼 배치되고 `.box`와 겹칠 수 있습니다.
- **B**: `.box`는 flex item으로 정상적인 흐름 안에 남아 있습니다. 형제 요소를 추가해도 flex 컨테이너가 알아서 배치하므로 레이아웃이 예측 가능하게 유지됩니다.

→ 지금은 자식이 `.box` 하나뿐이라 문제가 안 보이지만, **자식이 늘어나는 순간 A는 깨지고 B는 자연스럽게 대응**합니다.

### 2. 코드가 의도를 얼마나 직접적으로 드러내는가

- **A**는 `top: 50%; left: 50%; transform: translate(-50%, -50%)`라는 수치 트릭의 조합입니다. 처음 보는 사람은 "왜 -50%인가"를 계산해봐야 의도(중앙 정렬)를 알 수 있습니다.
- **B**는 `justify-content: center; align-items: center`로 의도가 코드 자체에 그대로 쓰여 있습니다.

→ 유지보수자가 코드를 읽고 의도를 파악하는 비용이 A가 더 큽니다.

### 3. 확장 시나리오에서의 견고성

| 상황 | A (absolute) | B (flex) |
|---|---|---|
| 형제 요소 추가 | 겹침 발생 가능 | 자동으로 옆/줄바꿈 배치 |
| 정렬 기준 변경 (예: 왼쪽 정렬로) | `top`/`left`/`transform` 재계산 필요 | `justify-content` 값만 교체 |
| 여러 자식 간격 조정 | 각 자식마다 개별 좌표 계산 | `gap` 한 줄 추가 |
| `.wrap`에 padding 추가 | containing block 계산에 유의 필요 | 자동 반영 |

B는 요구사항이 바뀌어도 속성 하나만 바꾸면 대응되지만, A는 매직 넘버를 다시 계산해야 하는 경우가 많습니다.

### 4. 부수효과(side effect)

- `position: absolute`는 stacking context, z-index 관리, 다른 absolute 요소와의 상호작용 등 레이아웃 외적인 복잡도를 함께 끌고 옵니다.
- flex는 표준적인 레이아웃 모델이라 다른 CSS 속성(margin, gap 등)과 상호작용이 예측 가능합니다.

### 참고: A가 더 적합한 경우도 있다

공정하게 보면 A(absolute+transform) 방식이 유리한 상황도 존재합니다.

- 오버레이/뱃지/모달처럼 **의도적으로 다른 요소 위에 겹쳐야** 할 때
- `.wrap`이 이미 다른 용도(grid, 다른 flex 방향 등)로 쓰이고 있어 `display: flex`를 새로 걸 수 없을 때
- `transform`은 GPU 가속되어 reflow 없이 처리되므로, 이 요소만 애니메이션시킬 계획이라면 성능상 이점이 있음

하지만 이번 문제처럼 **"자식 하나를 그냥 가운데 놓는" 일반적인 상황**에서는 B가 흐름을 유지하고 의도가 명확하며 확장에 강하므로 유지보수·견고성 면에서 우세합니다.

## 결론

| 기준 | A (absolute+transform) | B (flex) |
|---|---|---|
| 문서 흐름 유지 | ✗ | ✓ |
| 의도 가독성 | 낮음 (매직 넘버) | 높음 (명시적 속성명) |
| 형제 요소 추가 시 안정성 | 취약 | 안정적 |
| 확장성 (정렬 변경, gap 등) | 재계산 필요 | 속성 교체만으로 대응 |
| 적합한 특수 상황 | 오버레이/겹침 배치 | 일반적인 중앙 정렬 |

**정답: B(flexbox)** — 문서 흐름을 유지하면서 의도를 명시적으로 드러내고, 자식 요소나 정렬 요구사항이 바뀌어도 최소한의 수정으로 대응할 수 있기 때문입니다.
