## 답변

### 1. 정의

SPA(Single Page Application)는 최초 접속 시 브라우저가 HTML 문서 한 장을 받아온 뒤, 이후의 페이지 전환·화면 갱신을 서버로부터 새 HTML을 다시 받지 않고 JavaScript가 DOM을 직접 조작해서 처리하는 웹 애플리케이션 구조를 말한다. 필요한 데이터만 API(fetch/XHR)로 비동기 요청해 받아오고, 화면은 클라이언트에서 다시 그린다.

### 2. 동작 원리

1. **최초 로드**: 서버가 최소한의 `index.html`과 번들된 JS/CSS를 응답한다. 이 시점에는 `<div id="root"></div>` 정도만 있고 실제 콘텐츠는 비어 있는 경우가 많다.
2. **클라이언트 렌더링**: 브라우저가 JS 번들을 실행해 화면을 그린다(React/Vue 등의 프레임워크가 DOM을 구성).
3. **클라이언트 라우팅**: 사용자가 링크를 클릭하면 실제로는 서버에 새 페이지를 요청하지 않고, `History API`(`pushState`, `popState`)로 URL만 바꾸고 JS가 해당 경로에 맞는 컴포넌트를 다시 렌더링한다.
4. **데이터 통신**: 화면 갱신에 필요한 데이터는 REST/GraphQL API 등을 통해 JSON으로 비동기 요청한다. 서버는 더 이상 HTML을 만들어주는 역할이 아니라 데이터만 제공하는 역할로 축소된다.

### 3. MPA(Multi Page Application)와의 비교

| 구분 | MPA | SPA |
|---|---|---|
| 페이지 전환 | 매번 서버에 새 HTML 요청, 전체 새로고침 | 클라이언트 라우팅, 부분 갱신 |
| 초기 로딩 | 상대적으로 빠름(필요한 페이지만) | 번들 전체를 받아야 해서 상대적으로 느림 |
| 페이지 전환 속도 | 느림(매번 리로드) | 빠름(필요한 데이터만 통신) |
| 서버 부하 | HTML 렌더링까지 서버가 담당 | API 응답(JSON)만 담당해 상대적으로 가벼움 |
| SEO | 유리(완성된 HTML 제공) | 불리(초기 HTML이 비어있음, 별도 대응 필요) |

### 4. 장점

- 페이지 전환 시 화면 깜빡임 없이 부드러운 사용자 경험(UX) 제공
- 필요한 데이터만 서버에 요청하므로 네트워크 트래픽 절감
- 프론트엔드와 백엔드의 역할이 명확히 분리되어(백엔드는 API만 제공) 개발 및 유지보수 분리가 쉬움
- 하나의 코드베이스로 웹앱을 네이티브 앱처럼(App-like) 만들 수 있음

### 5. 단점과 대응 방안

- **SEO 문제**: 검색엔진 크롤러가 최초 HTML만 읽으면 콘텐츠가 비어있어 색인이 어려움
  → **SSR(Server Side Rendering)**(Next.js, Nuxt.js 등) 또는 **SSG(Static Site Generation)**, **프리렌더링(Prerendering)**으로 완성된 HTML을 미리 제공해 해결
- **초기 로딩 속도**: JS 번들 전체를 먼저 받아야 화면이 뜨기 시작함
  → **코드 스플리팅(Code Splitting)**, **지연 로딩(Lazy Loading)**으로 초기 번들 크기를 줄여 대응
- **상태 관리 복잡도**: 페이지 새로고침이 없다 보니 전역 상태·캐시가 누적되어 관리가 복잡해짐
  → Redux, Zustand, React Query 등 상태 관리 라이브러리로 대응
- **접근성/뒤로가기 이슈**: 라우팅을 직접 구현하면 브라우저 히스토리 동작이 깨질 수 있음
  → React Router, Vue Router 등 검증된 라우팅 라이브러리 사용

### 6. 대표 구현체

- **프레임워크/라이브러리**: React, Vue, Angular
- **라우팅**: React Router, Vue Router
- **SSR 프레임워크**(SPA의 SEO 단점 보완): Next.js, Nuxt.js

### 7. 한 줄 요약

SPA는 최초 1회 HTML을 로드한 뒤 이후의 화면 전환을 클라이언트 JS가 담당하고, 서버와는 데이터(JSON)만 주고받는 방식의 웹 애플리케이션 구조로, UX와 개발 구조 분리 면에서 이점이 있지만 SEO·초기 로딩 속도는 SSR/코드 스플리팅 등으로 보완해야 한다.
