## 답변

### 한 줄 정의

Debounce는 **연속으로 발생하는 이벤트를 묶어서, 마지막 호출 이후 일정 시간 동안 추가 호출이 없을 때만 함수를 한 번 실행하는 기법**이다. 엘리베이터 문이 닫히려다가 누가 타면 다시 열리고, 아무도 안 타야 비로소 닫히는 것과 같다.

원래는 **하드웨어 용어**다. 물리 스위치를 누르면 접점이 미세하게 튀면서(bouncing) 신호가 여러 번 들어오는데, 이를 하나로 정리하는 회로를 de-bounce라 불렀다.

### 왜 필요한가

브라우저 이벤트는 사람이 예상하는 것보다 훨씬 자주 발생한다.

| 이벤트 | 발생 빈도 |
|---|---|
| `input` (타이핑) | 글자 하나당 1회 |
| `resize` | 창을 끄는 동안 수십~수백 회 |
| `scroll` | 스크롤 1회에 수십 회 |

여기에 그대로 API 호출이나 무거운 계산을 붙이면 **불필요한 네트워크 요청·리렌더링·레이아웃 계산**이 폭발한다. "검색어 자동완성"에서 `abcde`를 치면 요청이 5번 나가고, 심지어 **응답 순서가 뒤바뀌어 `abc`의 결과가 `abcde` 결과를 덮어쓰는 race condition**까지 생긴다.

Debounce는 이 중 **의미 있는 마지막 시점 하나만** 남긴다.

### 동작

```
입력:   a   b   c        d               (delay 300ms)
타이머: ├─x ├─x ├───────x ├──────실행─→
결과:                              1회 호출 ("abcd")
```

호출이 들어올 때마다 **이전 타이머를 취소하고 새로 건다.** delay 동안 조용하면 그때 실행된다.

### 구현

```js
function debounce(fn, delay) {
  let timer;
  return function (...args) {
    clearTimeout(timer);                       // 핵심: 이전 예약 취소
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

const onSearch = debounce((keyword) => {
  fetch(`/api/search?q=${keyword}`);
}, 300);
```

- `timer`를 **클로저**에 가둬서 호출 간에 상태를 유지하는 것이 핵심
- `fn.apply(this, args)`로 `this`와 인자를 그대로 전달 (화살표 함수로 감싸면 상위 `this` 유지)

React에서는 렌더링마다 함수가 새로 생성되면 타이머도 매번 새로 만들어져 debounce가 **동작하지 않는다.** 반드시 참조를 고정해야 한다.

```jsx
// 잘못된 예 — 렌더링마다 새 debounce 인스턴스 생성
const handler = debounce(search, 300);

// 올바른 예
const handler = useMemo(() => debounce(search, 300), []);
useEffect(() => () => handler.cancel(), [handler]); // 언마운트 시 정리
```

### Throttle 과의 차이

가장 자주 나오는 비교다. 둘 다 호출 횟수를 줄이지만 **줄이는 방식이 다르다.**

| | Debounce | Throttle |
|---|---|---|
| 기준 | 마지막 호출 후 delay 경과 | 일정 주기마다 1회 |
| 폭풍 입력 중 | **실행 안 함** | 주기마다 계속 실행 |
| 보장 | 마지막 값은 반드시 반영 | 중간 상태도 주기적으로 반영 |
| 적합 | 검색어 입력, 자동 저장, resize 완료 후 재계산 | 스크롤 위치 추적, 무한 스크롤, 마우스 이동 |

> **최종 결과만 중요하면 Debounce, 진행 과정도 중요하면 Throttle.**

### 주의점

1. **delay 값**: 검색어 자동완성은 보통 200~400ms. 너무 짧으면 효과가 없고, 500ms를 넘으면 사용자가 느리다고 느낀다.
2. **즉시 실행이 필요한 경우**: 첫 호출을 바로 실행하는 `leading` 옵션(lodash `debounce(fn, delay, { leading: true, trailing: false })`)을 쓴다. 중복 제출 방지 버튼이 대표적.
3. **취소(cancel) 처리**: 컴포넌트 언마운트나 라우팅 이동 시 대기 중인 타이머를 정리하지 않으면 사라진 컴포넌트에 setState가 일어난다.
4. **debounce는 race condition을 없애주지 않는다**: 요청 수를 줄일 뿐이므로, 응답 역전이 문제라면 `AbortController`로 이전 요청을 취소해야 완전하다.

### 요약

> Debounce는 **"조용해질 때까지 기다렸다가 한 번만 실행"** 하는 패턴이다. 매 호출마다 이전 타이머를 취소하는 것이 구현의 전부이고, React에서는 함수 참조를 고정하지 않으면 무용지물이 된다. Throttle과의 차이는 "마지막 결과만 필요한가, 과정도 필요한가"로 구분한다.
