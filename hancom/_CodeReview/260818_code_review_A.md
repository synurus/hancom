먼저 실행 전 예상 → 실제 비교부터 해볼게요.

예상: 버튼을 3번 누르면 콘솔도 1, 2, 3이 찍히고, 화면의 클릭 3으로 같이 바뀔 거라 기대하기 쉽습니다.

실제 결과

콘솔: 변수 값: 1
콘솔: 변수 값: 2
콘솔: 변수 값: 3

하지만 화면의 버튼은 3번 눌러도 계속 **클릭 0**에 멈춰 있습니다.

Q1. 콘솔의 숫자와 화면의 숫자가 같을까?

아니요, 다릅니다. 콘솔은 1 → 2 → 3으로 정상적으로 올라가지만, 화면은 0에서 전혀 움직이지 않습니다.

Q2. 왜 이런 결과가 나올까? (원인 라인)
js
let count = 0;  // ← 바로 이 줄이 원인

핵심은 React가 화면을 다시 그리는(리렌더링) 조건입니다. React는 컴포넌트 함수 안의 아무 변수나 값이 바뀐다고 알아서 화면을 다시 그려주지 않습니다. React는 오직 두 가지 신호에만 반응해요: state가 바뀌거나, props가 바뀌는 경우뿐입니다.

지금 count는 let으로 선언된 그냥 평범한 지역 변수예요. React 입장에서는 이 변수가 존재하는지도 모르고, 이 값이 바뀌는지 감시하고 있지도 않습니다.

js
const click = () => {
  count++;  // 값은 실제로 1씩 올라감 (그래서 console.log는 정확히 찍힘)
  console.log('변수 값:', count);
  // 여기서 끝. React한테 "화면 다시 그려줘"라고 알려주는 코드가 없음
};

count++는 자바스크립트 레벨에서는 분명히 실행되고 값도 바뀝니다. 그래서 console.log는 정확하게 1, 2, 3을 찍는 거예요. 문제는 그 변경을 React에게 "알리는" 절차가 아예 없다는 것. React는 "이 컴포넌트를 다시 실행(리렌더링)해서 화면을 새로 그려야 하는가?"를 판단할 때, let count같은 일반 변수의 변화는 전혀 참고하지 않습니다. 그래서 함수는 다시 실행되지 않고, 화면엔 처음 렌더링됐을 때의 count = 0이 계속 남아있는 거예요.

해결 방법

useState로 count를 React가 추적하는 state로 만들어야 합니다.

jsx
import { useState } from 'react';

const App = () => {
  const [count, setCount] = useState(0);  // state로 선언

  const click = () => {
    setCount(count + 1);  // setter를 호출해야 React가 리렌더링을 트리거함
    console.log('변수 값:', count + 1);
  };

  return <button onClick={click}>클릭 {count}</button>;
};

export default App;

setCount(...)를 호출하는 순간 React는 "이 컴포넌트의 state가 바뀌었으니 다시 그려야겠다"고 인식하고, 컴포넌트 함수를 처음부터 다시 실행해서 새로운 count 값으로 화면을 갱신합니다.

한 걸음 더 — "그냥 변수 바꾸기"와 "state 바꾸기"의 근본적 차이
    let count = 0    useState(0)
값 변경    JS 레벨에서는 됨    React가 관리하는 저장소에 새 값 저장
React가 감지?    ✗ 전혀 모름    ✓ 변경을 감지하고 리렌더링 예약
화면 갱신    안 됨    됨
값이 유지되는 범위    함수가 다시 호출(리렌더링)되면 0으로 초기화됨    리렌더링돼도 값 유지됨

이게 React를 처음 배울 때 가장 흔히 걸리는 함정 중 하나예요. "화면에 보여줄 값이니까 그냥 변수에 담아서 조작하면 되겠지"라는 직관은 일반 JS에서는 맞지만, React는 "값이 바뀌었다"는 사실 자체보다 **"state가 바뀌었다는 걸 React가 알고 있는가"**를 기준으로 동작하기 때문에, state로 선언되지 않은 값은 아무리 바뀌어도 화면에 반영되지 않습니다.
