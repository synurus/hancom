# SSG(Static Site Generation) 설명 요약

## 정의
SSG(정적 사이트 생성)는 웹페이지를 **빌드(build) 시점에 미리 HTML로 생성**해두는 렌더링 방식입니다. 사용자가 요청할 때마다 서버가 페이지를 만드는 것이 아니라, 배포 전에 모든 페이지를 미리 만들어 정적 파일(HTML/CSS/JS)로 저장해두고, 요청이 오면 이 파일을 그대로 응답합니다.

## 동작 방식
1. 개발자가 빌드 명령을 실행하면, 데이터(API, DB, 마크다운 등)를 가져와 각 페이지의 HTML을 미리 생성합니다.
2. 생성된 정적 파일들은 CDN이나 정적 파일 서버에 배포됩니다.
3. 사용자가 접속하면 서버는 이미 만들어진 HTML을 즉시 반환합니다(런타임 렌더링 없음).

## 다른 렌더링 방식과 비교
| 방식 | 렌더링 시점 | 특징 |
|---|---|---|
| CSR (Client-Side Rendering) | 브라우저(요청마다) | JS가 브라우저에서 HTML을 그림, 초기 로딩 느림 |
| SSR (Server-Side Rendering) | 서버(요청마다) | 요청 시점마다 서버에서 HTML 생성 |
| **SSG** | **빌드 시점(미리)** | 배포 전에 HTML을 미리 생성, 요청 시 즉시 응답 |
| ISR (Incremental Static Regeneration) | 빌드 시점 + 주기적 재생성 | SSG의 단점(콘텐츠 최신성)을 보완 |

## 장점
- **속도**: 이미 만들어진 파일을 그대로 서빙하므로 응답이 매우 빠름
- **서버 부하 감소**: 요청마다 렌더링할 필요가 없어 서버 자원 절약
- **SEO에 유리**: 검색엔진이 완성된 HTML을 바로 크롤링 가능
- **CDN 캐싱 용이**: 정적 파일이므로 전 세계 CDN에 배포하기 쉬움
- **안정성**: 서버/DB 장애와 무관하게 페이지 제공 가능

## 단점
- **콘텐츠 최신성 문제**: 데이터가 바뀌어도 재빌드하지 않으면 반영되지 않음
- **빌드 시간 증가**: 페이지 수가 많아지면 빌드 시간이 길어짐
- **실시간/개인화 콘텐츠에 부적합**: 사용자별로 다른 데이터를 보여줘야 하는 페이지에는 적합하지 않음

## 적합한 사용 사례
- 블로그, 문서 사이트, 마케팅 랜딩 페이지처럼 콘텐츠 변경이 잦지 않은 사이트
- 대표적 프레임워크/도구: Next.js(`getStaticProps`), Gatsby, Hugo, Jekyll, Astro 등
