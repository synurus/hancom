# 코드 리뷰 보고서 — 장바구니 총금액 계산

- **대상 파일**: `260810_code_review_Q.js`
- **주제**: 3주차 · JS — 문자열/숫자 타입 강제변환(coercion)
- **작성일**: 2026-08-10

---

## 1. 코드 요약

```js
const price = '12000';  // 폼에서 입력받은 상품 가격 (문자열!)
const delivery = 3000;  // 배송비 (숫자)

const total = price + delivery;

console.log('상품 가격:', price);
console.log('최종 금액:', total);
```

## 2. 실행 결과

```
상품 가격: 12000
최종 금액: 120003000
```

두 번째 줄이 예상(`15000`)과 다릅니다.

---

## 3. 질문별 답변

### Q1. 어느 줄이 예상과 다른가요?

**두 번째 줄 `최종 금액:`** 입니다.
기대값은 `15000`이지만 실제로는 **`120003000`** 이 출력됩니다.
첫 줄은 `12000`으로 정상처럼 보이지만, 사실 이 값은 숫자가 아니라 **문자열** `'12000'` 입니다. `console.log`는 따옴표를 보여주지 않기 때문에 눈으로는 구분이 안 됩니다.

### Q2. 왜 그 값이 나왔나요? (원인 한 줄)

원인이 되는 줄은 **13번째 줄**입니다.

```js
const price = '12000';   // ← 숫자가 아니라 '문자열'
```

그리고 이 값이 실제로 문제를 일으키는 지점은 16번째 줄입니다.

```js
const total = price + delivery;   // 문자열 + 숫자 → 문자열 이어붙이기
```

**JavaScript의 `+` 연산자는 두 가지 일을 합니다.**

| 피연산자 | `+`의 동작 | 결과 |
|---|---|---|
| 숫자 + 숫자 | 덧셈 | `12000 + 3000 → 15000` |
| 문자열이 하나라도 있으면 | **문자열 연결** | `'12000' + 3000 → '120003000'` |

즉 `'12000' + 3000` 에서 JS는 숫자 `3000`을 문자열 `'3000'`으로 바꾼 뒤 이어붙여 `'120003000'`(길이 9의 문자열)을 만듭니다. `typeof total`은 `'number'`가 아니라 `'string'`입니다.

> 참고: `-`, `*`, `/`는 문자열 연결 기능이 없어서 반대로 동작합니다.
> `'12000' - 3000 → 9000`, `'12000' * 1 → 12000`
> **`+`만 유일하게 이런 함정이 있습니다.**

### Q3. 어떻게 해결할까요?

계산 **직전이 아니라, 값이 들어오는 입구에서 숫자로 바꾸는 것**이 원칙입니다.

**해결책 1 — `Number()` (권장)**

```js
const price = Number('12000');   // 12000 (숫자)
const delivery = 3000;

const total = price + delivery;  // 15000
```

**해결책 2 — 단항 `+` 연산자 (짧은 표현)**

```js
const total = +price + delivery; // 15000
```

**해결책 3 — 폼 입력값을 받는 지점에서 변환 (실무에서 가장 흔한 형태)**

```js
const price = Number(document.querySelector('#price').value);

if (Number.isNaN(price)) {
  // 숫자가 아닌 값이 들어온 경우 처리
}
```

## 4. 변환 방법 비교 — 무엇을 쓸까?

| 입력값 | `Number(v)` | `parseInt(v, 10)` |
|---|---|---|
| `'12000'` | `12000` | `12000` |
| `'12000원'` | `NaN` | `12000` |
| `'12,000'` | `NaN` | **`12`** ⚠️ |
| `''` (빈 문자열) | `0` ⚠️ | `NaN` |
| `'abc'` | `NaN` | `NaN` |

- **`Number()`**: 순수한 숫자 문자열만 허용. 이상한 값은 `NaN`으로 걸러지므로 **검증에 유리**. 다만 빈 문자열이 `0`이 되는 점은 주의.
- **`parseInt()`**: 앞에서부터 읽다가 숫자가 아니면 멈춤. `'12,000'`이 `12`가 되어버리는 **조용한 오류**가 위험합니다.

→ 가격/수량 같은 금액 계산에는 **`Number()` + `Number.isNaN()` 검사** 조합을 권장합니다.

## 5. 이 코드에서 배울 점

1. **`console.log`는 타입을 숨긴다.** `12000`과 `'12000'`이 똑같이 보입니다. 의심되면 `console.log(typeof price, price)`로 확인하세요.
2. **`+`는 문자열이 하나만 섞여도 연결로 돌변한다.** 이번 버그의 본질입니다.
3. **폼(`input.value`), `localStorage`, URL 쿼리스트링, JSON 등에서 온 값은 전부 문자열입니다.** 이런 값은 받는 즉시 숫자로 변환하는 습관을 들이세요.
4. **에러가 나지 않아서 더 위험합니다.** `120003000`은 예외 없이 그대로 화면에 표시되거나 결제 요청에 실려 갈 수 있습니다.
