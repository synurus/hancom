# prompt-review — 시스템 설계도

> 5주차 프롬프트 리뷰 시스템. 무엇이 무엇을 부르고, 어디서 멈추는가.

---

## 1. 전체 그림

```
  ┌─ 내 PC ─────────────────────────────────────────────┐
  │                                                      │
  │   ~/.claude/projects/                                │
  │     └ <프로젝트>/<세션ID>.jsonl   ← 자동으로 쌓인다   │
  │                    │                                 │
  │                    │ ① 용량순 정렬                    │
  │                    ▼                                 │
  │        ┌───────────────────────┐                     │
  │        │  extract_prompts.py   │  ② 사람이 친 것만    │
  │        │  (기계 — 판단 안 함)   │     남긴다           │
  │        └───────────┬───────────┘                     │
  │                    │  다이제스트 (10MB → 7KB)         │
  │                    ▼                                 │
  │        ┌───────────────────────┐                     │
  │        │      SKILL.md         │  ③ 읽고 판단한다     │
  │        │  (판단 — 규칙은 문서)  │                     │
  │        └───────────┬───────────┘                     │
  │                    ▼                                 │
  │        ~/Downloads/[프로젝트]_[세션ID]_개선점.md      │
  │                    │                                 │
  └────────────────────┼─────────────────────────────────┘
                       │
                       │  ④ 공유 여부는 본인이 정한다
                       ▼
              팀에는 **패턴만** 가져간다 (원문 인용 없이)
```

**저장소로 아무것도 안 나간다.** 3주차 `/codebook`·4주차 `/cleanflow` 가 PR 로 끝났던 것과 정반대다. 그 이유는 §5.

---

## 2. 입력과 출력

| | |
|---|---|
| **입력** | 없음. (`/prompt-review` 한 줄이면 된다) |
| 선택 입력 | 특정 프로젝트·세션을 지목할 때만 경로 |
| **출력 1** | `~/Downloads/[프로젝트]_[세션ID앞8자리]_개선점.md` |
| **출력 2** | 없음 — PR 도, 저장소 파일도, 채널 알림도 없다 |

**"무엇이 문제인지"는 입력받지 않는다.** 4주차와 같다. 로그를 읽고 시스템이 찾는다.

**경로를 입력받지 않는 것도 설계다.** 로그 위치는 사람마다 다르고, 자기 세션 ID 를 외우고 다니는 사람은 없다. 하드코딩된 경로가 하나라도 들어가면 **만든 사람만 쓸 수 있는 스킬**이 된다.

## 3. 처리 흐름 — 멈추는 지점이 셋

```
        시작  /prompt-review
          │
          ▼
   ┌──────────────────┐
   │ ① 세션을 찾는다   │  ~/.claude/projects/ 전체 · 용량 내림차순
   └────────┬─────────┘  (subagent 로그 제외)
            │  로그가 없다
            ├──────────────────────────▶  ✋ 멈춤 ①  "분석할 세션이 없습니다"
            │
            ▼
   ┌──────────────────┐
   │  가장 큰 것 하나  │  = 가장 오래 굴린 세션 = 습관이 가장 많이 드러난다
   └────────┬─────────┘
            ▼
   ┌──────────────────┐
   │ ② 추출           │  사람이 친 프롬프트만 (§4)
   └────────┬─────────┘
            │  프롬프트가 너무 적다
            ├──────────────────────────▶  ✋ 멈춤 ②  "표본이 부족합니다"
            │
            ▼
   ┌──────────────────┐
   │  기계적 신호      │  개수 · 길이 중앙값 · 단문 비율 · 되돌리기 신호어
   └────────┬─────────┘  ※ 어디를 먼저 읽을지 정하는 용도. 결론이 아니다
            ▼
   ┌──────────────────┐
   │ ③ 전문을 읽는다   │  재작업 사슬 추적 → 패턴 → 원문 인용
   └────────┬─────────┘
            │  되돌아간 곳이 없다
            ├──────────────────────────▶  ✋ 멈춤 ③  "이 세션은 됐습니다"
            │
            ▼
   ┌──────────────────┐
   │  리포트 작성      │  잘 통한 것 ≥ 1 · 아쉬운 점 3~5 · 말투 표 · 체크리스트
   └────────┬─────────┘
            ▼
      ~/Downloads/ 에 저장 → 경로를 알려준다
            │
            ▼
      ④ 활용은 사람이 한다
      (다음 세션에서 써보고, 며칠 뒤 다시 재본다)
```

**멈춤 ③이 이 시스템의 성격을 정한다.** 4주차의 *"이 파일은 됐습니다"* 와 같은 자리다. 무슨 로그를 넣어도 지적이 나온다면 그건 분석이 아니라 트집 생성기다.

## 4. 추출 구조 — 이 시스템이 성립하는 이유

로그 한 세션은 **10MB 를 넘는다.** 그대로는 읽을 수 없다. 그런데 걸러내고 나면 **7KB** 다.

```
  로그 한 줄 = JSON 한 개
       │
       ├─ type ≠ user            ──▶ 버림   (AI 응답 · 메타 · 스냅샷)
       ├─ isSidechain            ──▶ 버림   (서브에이전트 대화)
       ├─ isMeta                 ──▶ 버림   (자동 주입 알림)
       ├─ content = tool_result  ──▶ 버림   ← 개수로는 이게 제일 많다
       ├─ content = image        ──▶ 버림   ← 용량으로는 이게 제일 크다 (base64)
       ├─ 시스템·훅 주입 문자열   ──▶ 버림   ← 사람이 친 것처럼 생겼다
       │
       └─ 나머지                 ──▶ **사람이 친 프롬프트**
```

### 왜 이 필터가 핵심인가

| 안 거르면 | 리포트가 이렇게 된다 |
|---|---|
| `tool_result` 를 남기면 | "사용자가 파일 내용을 통째로 붙여넣었다" — 붙여넣은 적 없다 |
| 이미지를 남기면 | 읽기 전에 용량으로 터진다 |
| 훅 주입을 남기면 | "사용자가 같은 말을 반복했다" — 시스템이 넣은 문자열이다 |

**로그에서 `user` 로 표시된 것의 절반 이상이 사람이 친 게 아니다.** 이 구분을 못 하면 분석 전체가 허구가 된다. 그래서 이 부분만은 **판단이 아니라 코드**로 고정했다.

### 기계와 판단의 경계

```
  extract_prompts.py                    SKILL.md
  ──────────────────────                ──────────────────────
  찾는다 (용량순 정렬)                   읽는다 (전문)
  거른다 (위 필터)                       판단한다 (패턴 · 재작업 사슬)
  센다   (개수 · 길이 · 신호어)          쓴다   (인용 · 재작성 예시)

  틀리면 숫자가 어긋난다                 틀리면 리포트가 헛소리가 된다
  → 확인 가능                            → §5 규칙으로 막는다
```

4주차가 커밋을 **이동/주석**으로 쪼갠 것과 같은 이유다. 섞으면 어디까지가 사실이고 어디부터가 해석인지 알 수 없어진다.

## 5. 사생활 경계 — 다른 시스템과 반대로 설계한 유일한 부분

```
  3주차 codebook · 4주차 cleanflow          5주차 prompt-review
  ────────────────────────────────          ────────────────────────
  대상 = 저장소의 코드 (이미 공개)           대상 = 개인 대화 로그
  산출물 = PR · 저장소 md                    산출물 = 로컬 파일
  기본값 = 팀 전체가 본다                    기본값 = **아무도 안 본다**
  공유 = 자동                                공유 = 본인이 결정
```

**자동 공개가 기본값이면 아무도 안 돌린다.** 로그에는 시행착오·혼잣말·다른 프로젝트 이야기가 섞여 있고, 그게 팀에 그대로 보이는 걸 감수할 사람은 없다. **돌리지 않는 시스템은 없는 시스템이다.**

그래서 팀에는 이것만 올라간다.

```
  개인 리포트 (원문 인용 포함)   →   로컬에만
              │
              │  본인이 읽고 추린다
              ▼
  패턴 한 줄 (인용 없이)         →   팀 채널
    "나는 대상 파일을 자주 빠뜨리더라"
              │
              ▼
  넷 중 셋에게서 같은 패턴이 나오면
              ▼
  **개인 습관이 아니라 프로젝트의 구조 문제**
    (예: 파일 이름이 비슷해서 "그 파일"로 부르게 된다
     → 3주차 파일트리.md 처럼 경로를 붙여넣기 쉽게 만드는 쪽이 답)
```

**개인 교정으로 시작해 팀 규칙으로 끝난다.** 이 경로가 5주차를 개인 과제가 아니게 만드는 유일한 장치다.

## 6. 판단이 틀리는 것을 막는 구조

프롬프트 분석은 **아무 말이나 해도 그럴듯하게 들린다.** 사람의 습관에 대한 진술이라 반박 근거를 대기 어렵기 때문이다. 4주차가 추정 주석에 `※` 를 붙였던 것과 같은 장치가 필요하다.

```
        "이런 패턴이 있다" 고 쓰려 할 때
                    │
          ┌─────────┴──────────┐
          ▼                    ▼
   로그에서 원문을         원문을 못 찾겠다
   집어낼 수 있다               │
          │                    ▼
          ▼               **쓰지 않는다**
   인용을 붙여 쓴다         (추측으로 채우지 않는다)
```

| 막는 것 | 어떻게 |
|---|---|
| 없는 패턴 지어내기 | 원문 인용 없는 지적은 금지 (§5-1) |
| 숫자를 결론으로 쓰기 | 기계적 신호는 "어디를 읽을지"에만 사용 (§5-2) |
| 지적만 나열하기 | 잘 통한 것 최소 1개 강제 (§5-3) |
| 사람을 평가하기 | 패턴 이름으로만 지적 (§5-4) |
| 일반론으로 때우기 | 재작성 예시는 **그 세션의 실제 맥락**으로만 |

마지막이 제일 자주 깨진다. *"더 구체적으로 쓰세요"* 는 언제나 참이라서 언제나 쓸 수 있고, 그래서 아무것도 안 바꾼다.

## 7. 다른 시스템과의 관계

| 시스템 | 하는 일 | 이 시스템과의 차이 |
|---|---|---|
| 1주차 회의록 자동화 | 사람끼리의 대화를 남긴다 | prompt-review 는 **사람과 AI 의 대화**를 본다 |
| 2주차 `/알려주기` | 모르는 개념을 채운다 | 이쪽은 **아는 것을 전달하는 방식**을 본다 |
| 3주차 `/codebook` | 남의 **코드**를 읽을 진입로 | 이쪽은 남의 **지시문**을 읽을 진입로. 다만 로컬이라 공유 경로가 다르다 |
| 4주차 `/cleanflow` | 산출물(코드)의 품질 | 이쪽은 그 산출물을 **만들어낸 과정**의 품질 |

**1~4주차가 전부 산출물을 다뤘고, 5주차만 과정을 다룬다.**

```
   지시문  ──▶  AI  ──▶  산출물
      ▲                     ▲
      │                     │
  5주차 여기            1~4주차 전부 여기
```

그래서 이 시스템은 다른 넷과 **경쟁하지 않는다.** 오히려 4주차까지의 시스템을 더 잘 부리게 만드는 쪽에 가깝다 — `/cleanflow` 에 파일 경로를 안 적어서 되돌아간 것도, 이 리포트에는 재작업 사슬로 잡힌다.
