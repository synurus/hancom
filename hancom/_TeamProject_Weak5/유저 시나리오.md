# prompt-review — 유저 시나리오

> **prompt-review 를 쓰는 사람**의 이야기다. ZETEO 를 플레이하는 사람이 아니다.
> 사용자는 TeamB 팀원 넷이고, 쓰는 곳은 **각자의 PC** 다 — 3·4주차와 달리 디스코드가 아니다.

---

## 등장인물

| | 파트 | 이 시스템에서의 역할 |
|---|---|---|
| 유민성 | 서버 · DB | 자기 로그를 돌린다 |
| 김정현 | 봇 | 자기 로그를 돌린다 |
| 이현우 | 게임 화면 | 자기 로그를 돌린다 |
| 박진 | 공통 화면 | 자기 로그를 돌린다 |

**요청자와 대상이 항상 같다.** 3주차 코드북·4주차 cleanflow 는 남의 것을 다룰 수 있었지만, 여기서는 **자기 로그만** 다룬다. 남의 PC 안을 읽을 방법이 없고, 읽을 수 있어도 읽지 않는다.

---

## 시나리오 1 — 가장 오래 굴린 세션을 돌린다 (기본 경로)

**상황** 민성님이 서버 작업을 며칠째 한 세션에서 하고 있다. 결과물은 나왔는데 자꾸 되돌아간 느낌이 있다.

```
민성  터미널에서 한 줄

      /prompt-review

prompt-review
      ~/.claude/projects/ 를 훑는다 → 용량 내림차순

        10.9 MB  2026-08-21  Zeteo   5b624f99-…
         7.5 MB  2026-08-19  Zeteo   9c8e3c6e-…
         5.2 MB  2026-08-25  Zeteo   b46b9063-…

      가장 큰 것 하나를 고른다 (= 가장 오래 굴린 세션)
      추출 → 10.9 MB 에서 프롬프트 47개만 남는다

      📄 ~/Downloads/Zeteo_5b624f99_개선점.md 에 저장했습니다.

      한 줄 요약
        지시는 정확한데 성공 기준이 없어 세 번 되돌아갔습니다.

      잘 통한 것 1개 · 아쉬운 점 3개 · 다음 세션 체크리스트 4줄

민성  리포트를 연다

      아쉬운 점 ②  성공 기준 부재 — 프롬프트 18, 21번
      > "이거 좀 고쳐줘"
      18번 뒤에 21번에서 다시 방향을 잡았고, 23번에서 원복 요청이 나왔다.

      이렇게 썼다면
      > "재연결 시 타이머가 어긋나는 걸 고쳐줘.
      >  고친 뒤 방 두 개를 동시에 돌려서 시간이 맞는지 확인해줘."
```

**핵심** — **경로도, 세션 ID도, 무엇이 문제인지도 입력하지 않았다.** 한 줄이면 된다. 4주차 cleanflow 가 파일 경로 하나만 받았던 것보다 더 줄었다.

## 시나리오 2 — 아무것도 하지 않고 끝난다

**상황** 박진님이 어제 30분짜리 세션 하나로 CSS 토큰만 손봤다. 그 세션을 지목한다.

```
박진  /prompt-review   (어제 세션 지정)

prompt-review
      추출 → 프롬프트 6개

      전문을 읽는다
        · 되돌아간 곳 없음
        · 대상이 매번 명시돼 있음 (tokens.css)
        · 요구가 하나씩 분리돼 있음

      이 세션은 됐습니다. 리포트를 만들지 않았습니다.

      6개 전부 대상과 원하는 결과가 붙어 있어서 재작업이 없었습니다.
      다만 표본이 작아 습관을 판단할 근거는 못 됩니다 —
      며칠 더 쌓인 뒤 큰 세션으로 다시 돌려보시는 걸 권합니다.
```

**핵심** — **"이 세션은 됐습니다"가 정상 결과다.** 4주차의 *"이 파일은 됐습니다"* 와 같은 자리다. 무슨 로그를 넣어도 지적이 나온다면 그건 분석이 아니라 트집 생성기다.

## 시나리오 3 — 숫자가 오탐이었다

**상황** 현우님 세션의 기계적 신호에 **"20자 미만 단문 34%"** 가 찍혔다.

```
prompt-review
      기계적 신호
        · 프롬프트 52개 · 길이 중앙값 21자
        · 20자 미만 단문 18개 (34%)      ← 눈에 띈다
        · 되돌리기 신호어 9개

      → 단문 18개를 먼저 읽는다

      읽어보니
        "응 그렇게 해"        (직전 제안에 대한 승인)
        "위에 것만"           (두 후보 중 선택)
        "ㅇㅇ 맞아"           (확인)
        …
        18개 중 15개가 **직전 맥락이 살아 있는 응답**이었다.
        짧은 게 맞는 자리다.

      리포트에는 이렇게 적는다
        단문 비율(34%)은 문제 신호가 아니었습니다.
        18개 중 15개는 직전 제안에 대한 승인·선택이라
        짧은 것이 정확합니다. 나머지 3개만 아래에 다룹니다.
```

**핵심** — **숫자는 어디를 먼저 읽을지 정하는 데만 쓴다.** 신호를 그대로 결론으로 옮기면 *"프롬프트가 너무 짧습니다"* 같은, 틀렸는데 그럴듯한 리포트가 나온다. 되돌리기 신호어 9개도 마찬가지다 — *"아니면 이 방법은?"* 이 섞여 있다.

## 시나리오 4 — 리포트를 공유하지 않는다

**상황** 정현님 리포트가 나왔는데, 인용된 프롬프트에 봇 작업 얘기 말고도 개인적인 시행착오와 다른 프로젝트 이야기가 섞여 있다.

```
정현  리포트를 읽는다

      아쉬운 점 ①  여러 요구 한 덩어리 — 프롬프트 7번
      > "프롬프트 톤 좀 바꾸고, 그리고 아까 그 유출 검사도 다시 보고,
      >  아 그리고 어제 말한 거 그거 어떻게 됐지?"
      세 요구 중 마지막이 처리되지 않은 채 다음 프롬프트로 넘어갔다.

정현  이 인용은 팀에 안 올린다. 대신 #general 에 한 줄

      "저는 한 번에 세 개씩 던지는 습관이 있더라고요.
       마지막 하나가 매번 흘러갑니다."

      → 원문 인용 없이 패턴만
```

**핵심** — **자동 공개가 기본값이면 아무도 안 돌린다.** 3·4주차 산출물은 저장소에 올라가는 게 당연했지만, 로그에는 시행착오와 사적인 것이 섞여 있다. **돌리지 않는 시스템은 없는 시스템이다.** 그래서 리포트는 `~/Downloads/` 에만 남고, 무엇을 꺼낼지는 본인이 정한다.

## 시나리오 5 — 넷의 패턴이 겹쳐 팀 규칙이 된다

**상황** 넷이 각자 돌린 뒤 패턴만 채널에 올렸다.

```
민성   "대상 파일을 안 적어서 되돌아간 게 3번"
정현   "저도요. '아까 그 파일' 이라고 했다가 다른 걸 잡았어요"
현우   "저는 '그 화면' 이라고 했다가 MainScreen 대신 GameScreen 이 열렸습니다"
박진   (해당 없음 — CSS 는 파일이 몇 개 안 돼서 헷갈릴 일이 없었다)

      → 넷 중 셋에게서 같은 패턴
```

```
        이건 개인 습관인가?
                │
                ▼
        파일이 많고 이름이 비슷하다
        (screens/ 아래만 7개, 이름이 전부 …Screen)
                │
                ▼
        **프로젝트의 구조 문제일 수 있다**
                │
                ▼
        3주차 파일트리.md 가 이미 경로 목록이다.
        붙여넣기 쉽게 다듬는 쪽이 개인 교정보다 빠를 수 있다.
```

**핵심** — **개인 교정으로 시작해서 팀 규칙으로 끝난다.** 이게 5주차가 개인 과제가 아닌 이유다. 넷이 같은 곳에서 걸렸다면 고쳐야 할 것은 사람의 말버릇이 아니라 **환경**이다.

## 시나리오 6 — ④ 활용, 한 바퀴가 닫힌다

**상황** 시나리오 1로부터 나흘 뒤. 민성님이 체크리스트를 지키며 작업했다.

```
민성  나흘간 새 세션에서 작업
        □ 대상 파일 경로를 먼저 적는다        → 지킴
        □ "고쳐줘" 대신 확인 방법을 붙인다     → 대체로 지킴
        □ 요구는 한 번에 하나                 → 두 번 어김

민성  /prompt-review   (그 새 세션)

prompt-review
      이전 세션과 비교합니다.

                        8/21 세션    새 세션
        프롬프트          47개        39개
        되돌리기 신호어    7개         2개      ← 줄었다
        길이 중앙값       34자        61자

      "성공 기준 부재"는 이번 세션에 나타나지 않았습니다.
      "여러 요구 한 덩어리"는 2회 남아 있습니다 (프롬프트 12, 28번).

민성  #general 에 한 줄
      "체크리스트 쓰니까 되돌아가는 게 확 줄었습니다"
```

**핵심** — **여기까지가 한 바퀴다.** 4주차가 *"정리해놓고 안 써보면 그 배치가 쓸 만한지 알 수 없다"* 고 한 것과 같다. 리포트를 읽고 끝내면 검색해서 나오는 프롬프팅 가이드와 다를 게 없어진다. **다시 재봐야 그 조언이 맞았는지 알 수 있다.**

## 흐름 한눈에

```
/prompt-review ─▶ 세션 찾기 ─▶ 추출 ─┬─ 표본 부족 ─▶ "며칠 더 쌓인 뒤에"   (시나리오 2)
                  (용량순)            │
                                      └─ 충분 ─▶ 신호 ─▶ 전문 읽기
                                                            │
                                          ┌─────────────────┴──────────────┐
                                          ▼                                ▼
                                  되돌아간 곳 없음                   재작업 사슬 있음
                                  "이 세션은 됐습니다"                      │
                                     (시나리오 2)                          ▼
                                                                    리포트 저장
                                                                  ~/Downloads/
                                                                          │
                                          ┌───────────────────────────────┤
                                          ▼                               ▼
                                  본인만 본다 (시나리오 4)      패턴만 팀에 (시나리오 5)
                                          │                               │
                                          └───────────────┬───────────────┘
                                                          ▼
                                                  ④ 활용 (시나리오 6)
                                            다음 세션에서 써보고 다시 잰다
```

**숫자는 단서고, 인용이 근거고, 재측정이 판정이다.** (시나리오 3 → 1 → 6)
