세션 로그에 남은 **사용자 프롬프트만** 뽑아 읽고, 어떻게 쓰면 같은 결과를 더 적은 왕복으로 얻었을지 리포트로 남긴다. 코드 리뷰가 아니라 **프롬프트 리뷰**다 — 결과물의 품질이 아니라 지시문의 품질을 본다.

## 절차

**1. 세션 목록을 용량순으로 뽑는다.** 로그는 사람마다 다른 절대경로에 있으므로 하드코딩하지 말고 항상 스크립트로 찾는다.

```bash
python ~/.claude/skills/prompt-review/scripts/extract_prompts.py --list
```

`~/.claude/projects/` 전체를 훑어 용량 내림차순으로 출력한다(subagent 로그는 제외). 용량이 큰 세션 = 오래 굴린 세션 = 프롬프팅 습관이 가장 많이 드러나는 세션이다.

**2. 한 개만 고른다.** 기본값은 **1순위(가장 큰 것)**. 사용자가 특정 프로젝트·날짜를 지목했으면 그걸 쓴다. 여러 개를 한 번에 분석하지 않는다 — 리포트는 세션당 1개다.

**3. 다이제스트를 만든다.** 로그 원본은 base64 이미지 때문에 수 MB다. **절대 원본 .jsonl을 직접 읽지 말고** 스크립트를 거친다.

```bash
python ~/.claude/skills/prompt-review/scripts/extract_prompts.py "<절대경로>" --out "<스크래치패드>/digest.md"
```

tool_result·사이드체인·훅 주입·이미지 블록을 걷어내고 사람이 실제로 친 프롬프트만 시간순으로 남긴다. 맨 위 "기계적 신호"(프롬프트 수, 길이 중앙값, 단문 비율, 재지시 신호어 수)는 **단서일 뿐 결론이 아니다** — 짧은 프롬프트가 늘 나쁜 게 아니고, `⟲재지시신호` 표시도 오탐이 섞인다. 반드시 프롬프트 전문을 읽고 판단한다.

**4. 다이제스트를 읽고 분석한다.** 아래 관점으로 훑는다.

- **재작업 사슬**: N번 프롬프트 → 결과가 어긋남 → N+1번에서 "아니 그게 아니라". 이 사슬의 **첫 프롬프트에 무엇이 빠져 있었는지**가 리포트의 핵심 재료다.
- **맥락 없는 지시대명사**: "이거", "그 파일", "아까 그거" — 어느 파일/함수인지 로그상 특정되지 않는 경우.
- **한 프롬프트에 여러 요구**: 요구가 섞이면 하나만 처리되고 나머지가 흘러간다.
- **성공 기준 부재**: "고쳐줘", "잘 되게 해줘"처럼 무엇이 통과인지 없는 지시.
- **거대 붙여넣기**: 수천 자 덤프 + "봐줘". 어디를 봐야 하는지 없는 경우.
- **잘 된 것도 찾는다**: 절대경로를 준 프롬프트, 하지 말 것을 명시한 프롬프트 등 **실제로 잘 통한 사례**를 최소 1개는 인용한다. 지적만 나열하면 리포트가 안 읽힌다.

**5. 리포트를 저장한다.** 경로는 `~/Downloads/[프로젝트명]_[세션ID앞8자리]_개선점.md` — 다이제스트 헤더의 "저장 파일명"에 이미 계산되어 있으니 그대로 쓴다. 저장 후 절대경로를 사용자에게 알려준다.

## 리포트 형식

```markdown
# [프로젝트] 세션 프롬프팅 리뷰
> 로그: <절대경로> · 프롬프트 N개 · YYYY-MM-DD

## 한 줄 요약
(이 세션의 프롬프팅을 한 문장으로. 예: "지시는 정확하나 성공 기준이 없어 3번 되돌아갔다.")

## 잘 통한 것
- **(패턴 이름)** — 3번 프롬프트: `"..."` → 왜 잘 통했는지 한 줄.

## 아쉬운 점
### 1. (패턴 이름) — 프롬프트 12, 13, 15번
> `"실제 원문 인용"`

무슨 일이 벌어졌는지 2~3줄. (12번 뒤에 13번에서 방향을 다시 잡았고, 15번에서 원복 요청이 나왔다 — 처럼 **로그에서 확인되는 사실**만.)

**이렇게 썼다면:**
> `"고쳐 쓴 프롬프트 예시"`

(반복. 3~5개면 충분하다. 사소한 것까지 나열하지 않는다.)

## 추천 말투
| 상황 | 지금 말투 | 추천 말투 |
|---|---|---|
| 수정 요청 | `"아니 그거 말고"` | `"X는 유지하고 Y만 바꿔줘"` |
(세션에서 실제로 나온 말투만 왼쪽에 넣는다.)

## 다음 세션 체크리스트
- [ ] (이 세션에서 실제로 걸린 것만 3~5개)
```

## 규칙

- **원문 인용 없는 지적은 쓰지 않는다.** 모든 지적에는 몇 번 프롬프트인지와 실제 문장이 붙는다. 없는 패턴을 그럴싸하게 만들어내지 않는다.
- **사람이 아니라 패턴을 지적한다.** "성의 없다"가 아니라 "대상 파일이 빠졌다".
- **"이렇게 썼다면"은 반드시 그 세션의 실제 맥락으로 채운다.** 일반론("구체적으로 쓰세요")은 넣지 않는다.
- **로그에 없는 것을 추측하지 않는다.** 왜 그렇게 지시했는지 모르면 모른다고 쓰거나 빼고, 지어내지 않는다.
- 항목 수보다 정확도다. 아쉬운 점 3개짜리 리포트가 12개짜리보다 낫다.
