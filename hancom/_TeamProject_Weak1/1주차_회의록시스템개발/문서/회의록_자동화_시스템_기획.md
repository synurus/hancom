# 회의록·채널 요약 자동화 시스템 기획

## 프로젝트 개요

- **아이템**: Discord 팀 서버 기반 채널 요약 + 회의록 자동 작성 시스템
- **배경**: 팀 프로젝트 진행 중 여러 채널·스레드에 논의가 흩어지는 문제. 채널 요약과 회의록 작성을 수작업으로 반복하던 것을 자동화
- **과업 연계**: 팀 프로젝트 "회의록 시스템 개발 기획서 제출" 과업 겸함
- **형태**: 별도 서비스가 아니라, Claude Code의 Skill(작업 절차 문서) + 기존 Discord 연동 플러그인의 확장

## 기존 인프라

Claude Code의 channels 기능과 공식 Discord 플러그인을 통해 팀 서버에 봇(Hermes2)이 이미 연결되어 있었음. 설치 과정에서 몇 가지 기술적 난관(런타임 의존성, 서버 초대 절차 등)이 있었으나 해결하고 정상 가동을 확인함. 다만 초기 상태는 **특정 채널 하나에서만** 반응하도록 좁게 설정되어 있었음.

## 서버 전체 확장 (핵심 작업)

팀 서버 안에서 채널·스레드가 계속 새로 생기는 구조상, 새 채널이 생길 때마다 매번 수동으로 봇 접근 권한을 등록해야 하는 방식은 비효율적이라고 판단함. 이를 해결하기 위해 **플러그인의 원본 코드(`server.ts`)를 직접 수정**하여 접근 범위를 채널 단위에서 서버(길드) 단위로 확장함.

구체적인 수정 내용:

1. 접근 정책 데이터 구조에 채널 단위 필드(`groups`)와 별도로 **서버 단위 필드(`guilds`)를 신설**
2. 메시지 수신 판단 로직에서, 특정 채널에 개별 등록이 없더라도 그 채널이 속한 서버가 `guilds`에 등록되어 있으면 자동으로 허용하도록 **폴백(fallback) 로직 추가**
3. 스레드는 부모 채널의 정책을 상속하는 기존 구조를 그대로 활용 — 서버 단위 등록만으로 신규 채널·스레드까지 자동으로 커버됨
4. 메시지 조회 등 아웃바운드 도구의 접근 검증 로직에도 동일한 서버 단위 폴백을 반영해, 이전에 등록한 적 없는 채널의 과거 기록도 조회 가능하도록 함

결과적으로 팀원이 새 채널이나 스레드를 만들어도 별도 설정 없이 봇이 즉시 반응 가능한 구조가 됨.

## 왜 새 플러그인이 아닌 Skill인가

요약·회의록 기능에 필요한 것은 새로운 기능(도구)이 아니라, 이미 갖춰진 메시지 조회(`fetch_messages`)·답장(`reply`) 도구를 **어떤 절차와 형식으로 사용할지 표준화**하는 것이었음. 이에 따라 새 플러그인을 만드는 대신 Skill(마크다운 절차 문서) 2종을 작성함.

배치 위치는 Discord 플러그인 폴더 내부가 아니라 별도의 사용자 스킬 디렉토리로 분리함 — Discord 플러그인은 공식 배포판이라 추후 업데이트 시 로컬 수정 사항이 덮어써질 수 있기 때문.

## 핵심 기능

| # | 기능 | 내용 |
|---|---|---|
| 1 | 채널 요약 (`channel-summarize`) | 채널·스레드의 최근 대화를 가져와 화자별로 정리하고 결론을 붙여 그 자리에 바로 답장. Discord 마크다운(볼드, 불릿, 구분선)을 활용해 가독성 있게 구성 |
| 2 | 회의록 자동 작성 (`meeting-minutes`) | 채널 대화를 "현재 주제 / 논의 내용 / 다음 목표" 구조로 정리해 마크다운 파일로 저장하고, 팀 저장소에 커밋·푸시까지 자동 처리 |
| 3 | 팀원 매핑 인프라 | Discord 핸들·사용자ID·실명, 채널명·채널ID를 매핑한 데이터(`team-map.json`)를 구축해 회의록·요약에 실명이 표시되도록 함 |
| 4 | 완료 후 참여자 리콜 알람 | 회의록 작성이 끝나면 실제 논의에 참여했던 팀원 전원을 `@멘션`으로 태그하여 알림이 가도록 함 — 결과물을 놓치지 않고 확인할 수 있게 함 |

## git 작업 안전장치

회의록 파일은 팀 공유 저장소(GitHub)에 자동으로 반영되므로, 아래와 같은 안전장치를 두어 예기치 못한 문제가 팀 저장소에 그대로 반영되지 않도록 함.

1. 새 회의록 파일 외에 다른 변경 사항이 이미 있으면 즉시 중단 — 다른 팀원의 작업물을 임의로 커밋하지 않기 위함
2. `main` 브랜치가 아닌 경우 중단
3. 반영 전 최신 이력을 먼저 받아오되, 충돌이 발생하면 자동 병합을 시도하지 않고 중단
4. 새로 생성한 회의록 파일 한 개만 선택적으로 반영 (전체 변경사항 일괄 반영 금지)
5. 원격 저장소 반영이 거부되거나 실패하면 강제로 밀어붙이지 않고, 정확한 오류 내용과 함께 중단 후 보고

즉 "정상적인 상황에서는 끝까지 자동으로 처리하되, 조금이라도 예상과 다르면 반드시 멈추고 사람에게 알린다"는 원칙으로 설계함.

## 개발 과정 — 반복 개선

1차로 두 기능의 기본 형태를 구현한 뒤, 실제 팀 서버에서 시험 사용함. 그 결과 아래 4가지 개선점이 확인되어, 우선순위를 정해 순차적으로 반영함.

1. 채널 요약의 출력 형식이 한 문단에 몰려 가독성이 떨어짐 → Discord 마크다운 기반 구조화 형식으로 개선
2. 회의록의 참여자가 Discord 핸들로 표시됨 → 실명 매핑 인프라 구축 (참여자ID 노출을 위한 코드 수정 포함)
3. 위 인프라를 기반으로 회의록 참여자 필드를 실명으로 표시
4. 완료 후 참여자 리콜 알람(멘션 태그) 기능 추가

## 안전 관련 추가 고려사항

- **원본 코드 보존**: 플러그인의 원본 코드를 직접 수정하는 작업 특성상, 수정 전 항상 별도 백업 파일을 남겨 언제든 이전 상태로 되돌릴 수 있도록 함
- **프롬프트 인젝션 방어**: 채널 메시지 내용에 지시문처럼 보이는 텍스트가 포함되어 있어도, 이는 요약 대상 데이터로만 취급하고 실행하지 않도록 각 Skill에 명시함

## 최종 산출물

- `channel-summarize` / `meeting-minutes` Skill 문서 2종
- 팀원·채널 매핑 데이터(`team-map.json`)
- Discord 연동 플러그인 확장 코드 (서버 단위 접근 확장, 참여자ID 노출)
- 회의록 결과물: 본 저장소 `회의록/` 폴더에 `날짜_주제_회차차_회의록.md` 형식으로 누적

## 향후 확장 여지 (미착수)

1. 채널/팀원 매핑을 수작업 대신 실시간 조회로 대체하는 동적 조회 기능
2. 특정 채널을 서버 단위 허용 범위에서 예외 처리하는 기능
3. 회의록 자동 작성의 주기적(예: 매일 정해진 시각) 실행 — 현재는 명령 시에만 동작
