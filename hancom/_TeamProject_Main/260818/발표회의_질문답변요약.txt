"메시지 객체를 통째로 넘기면 최적화가 무효가 된다" — 설명 요약

1. React.memo가 하는 일

"prop이 전이랑 같으면 다시 그리지 마라" — 비교는 기본적으로 === 로 한다.

2. 객체의 ===는 "내용이 같은가"가 아니라 "같은 물건인가"

  { text: '안녕' } === { text: '안녕' }   // false

  '안녕' === '안녕'   // true

3. 소켓으로 오는 데이터는 매번 새 상자다

서버 메모리의 객체
    → socket.io가 JSON 문자열로 직렬화   ← 객체가 글자로 납작해짐
    → 네트워크로 전송
    → 브라우저가 JSON.parse로 복원       ← 완전히 새 객체가 만들어짐
    → setState(e.state)

4. 그래서 이렇게 넘기면 memo가 무효화된다

5. 왜 이게 중간발표자료에 남았는가

해결책.txt를 준 사람의 판단:
  "room.messages는 push로만 늘어나고 기존 객체는 절대 다시 안 만들어지므로
   m 객체 참조는 매 브로드캐스트마다 그대로 유지된다"
  → 그래서 message={m} 통째로 넘기는 코드를 제안했다.

이 문장은 서버 쪽만 보면 맞다. 다만 서버-브라우저 사이의 JSON 직렬화
경계를 계산에 안 넣은 것 — 서버 메모리의 객체 정체성과 브라우저가 받는
객체 정체성은 별개다.

최종 코드는 원시값으로 푸는 방향으로 갔고, 실제 Chat.tsx 주석에 이 이유가
남아 있다: "state는 브로드캐스트마다 소켓을 통해 JSON으로 새로 파싱돼
들어오므로, 내용이 같은 메시지라도 객체 참조는 매번 새로 생긴다."

질문 답변 — Chat.tsx: memo로 줄 단위는 막았는데 ChatLog 자체는
여전히 브로드캐스트마다 다시 실행된다. 무시할 만한 수준인가?

결론

맞다, ChatLog는 매 브로드캐스트마다 다시 실행된다. 하지만 무시할 만한 수준이다.
지금 게임 길이 기준으로 실측하면 브로드캐스트 1회당 0.05ms 이하다.

왜 ChatLog는 memo로 못 막았나

memo는 "자기가 감싼 컴포넌트의 경계"에서만 리렌더를 끊는다. ChatMessageRow를
감쌌으니 그 아래(Row 자신 + Avatar)는 스킵되지만, ChatLog 자신은 아무도 안
감쌌으니 MainScreen이 리렌더되면 무조건 한 번 더 호출된다.
memo는 "나를 부르지 마"가 아니라 "내 아래는 건드리지 마"다 — 구조상 피할 수 없다.

ChatLog까지 memo로 못 감싸는 이유

한 단계 더 감쌀 수는 있지만(memo(ChatLog)) 효과가 없다.
GameScreen.tsx가 modal을 매번 새로 만들고(JSX는 호출마다 새 객체),
messages·players도 소켓 JSON 파싱이라 매번 새 배열이다.
셋 다 참조가 매번 바뀌니 얕은 비교에서 항상 "다르다"가 나와 그대로
다시 실행된다
