## 0. 요약 — 이번에 정한 것

- 좁은 화면에서는 채팅/투표를 세로로 쌓되, **페이지 자체가 늘어나지 않는다** (B-1·B-2에서
  배운 것 재적용). 헤더·입력창·투표 바는 고정, 채팅 로그만 내부 스크롤.
- 투표 패널은 **접이식**(하단 고정 얇은 바 ↔ 펼침). 상태 전이는 탭이 아니라 **투표
  국면 자체로 자동 트리거**한다 — 펼침이 "투표가 시작됐다"는 신호를 겸한다.
- 컷신/시스템 이벤트 삽화는 채팅 로그에 상시 삽입하지 않고 **토스트/오버레이**로.
- 타이머는 헤더뿐 아니라 **투표 바(접힌 상태 포함)에도** 항상 노출.

## 1. 전체 레이아웃 (좁은 화면 기준)

네 영역으로 나누고, 스크롤은 채팅 로그 안에서만 일어난다. 나머지 셋은 화면에 고정.

```
┌──────────────────────────────────────┐
│ [2라운드] 토론 진행중        ⏱ 2:30   │ ← ① 헤더, 상단 고정
├──────────────────────────────────────┤
│                                        │
│   채팅 로그 (유일한 스크롤 영역)         │ ← ② 채팅 로그, 남는 공간 전부
│   A: ...                              │
│   B: ...                              │
│   (시스템) C님이 지목되었습니다          │
│                                        │
├──────────────────────────────────────┤
│  투표 바 / 패널 (접이식)                │ ← ③ 투표 영역, 하단 고정
├──────────────────────────────────────┤
│ [메시지 입력.....................] [전송] │ ← ④ 입력창, 최하단 고정
└──────────────────────────────────────┘
```

②만 `overflow-y: auto`, 나머지는 `flex-shrink: 0`. `.zt-screen`에 `height: 100vh`(또는
`dvh`) + `.zt-body`를 세로 flex로 바꾸는 정도로 지금 구조에서 확장 가능 — B-1/B-2 때 이미
`.zt-screen:has(.zt-body){height:100vh}` 패턴을 써봤으니 그 연장선.

## 2. 영역별 상세

### ① 헤더

기존 `Debate.tsx`의 `<header className="zt-head">` 그대로. `Timer` 컴포넌트 재사용.
좁은 화면에서도 상단 고정(`position: sticky` 또는 flex 레이아웃상 고정 영역)이라 스크롤
중에도 항상 보인다.

### ② 채팅 로그

`Chat.tsx` 그대로 재사용 — 컴포넌트 자체는 안 바뀐다. 바뀌는 건 감싸는 컨테이너의 높이
계산뿐(①③④를 뺀 나머지를 `flex: 1; min-height: 0`으로). 시스템 메시지는 기존 결정대로
배경 띠 처리 유지(디자인 결정 11). 큰 삽화/컷신은 이 로그 안에 넣지 않는다 → 4절.

### ③ 투표 바 / 패널 — 이번 대화의 핵심

#### 접힌 상태 (기본값 아님 — 투표 종료 후 상태)

```
┌──────────────────────────────────────┐
│ B (2표,내 선택)  D (3표)      ⏱ 1:23 │  ← 탭하면 펼침
└──────────────────────────────────────┘
```

- **득표 1표 이상인 후보만** 나열. 0표인 사람은 안 보인다.
- 내가 투표한 후보에는 "내 선택" 표시가 붙는다.
- 나열 순서는 **득표순 정렬이 아니라 기존 후보 순서(플레이어 목록 순)** 를 따른다 —
  `VotePanel`의 기존 원칙("정렬하지 않는다 — 표가 바뀔 때마다 목록이 튀면 클릭 대상이
  흔들린다", 디자인 결정 7)을 접힌 바에도 그대로 적용. 표가 바뀌어도 나열 순서 자체는
  안 튀고, 이미 있던 항목의 표만 갱신되거나 새 항목이 끼어드는 정도.
- **아직 아무도 투표 안 한 시점**(투표 막 시작)에는 후보가 하나도 없다 → 이때는
  `투표 진행 중            ⏱ 1:23` 처럼 안내 문구만 노출.
- 타이머는 접힌 상태에서도 항상 우측에 노출.

#### 펼친 상태

```
┌──────────────────────────────────────┐
│ 투표 현황                     ⏱ 1:23 ▼│
│  A                       0표          │
│  B  (내 선택)              2표          │
│  C                       0표          │
│  D                       3표          │
│  기권                                 │
└──────────────────────────────────────┘
```

- 기존 `VotePanel.tsx`를 거의 그대로 재사용 — 전원 목록(0표 포함) + 득표 수 + 정렬 안 함.
- **변경점 하나**: 기권을 별도 버튼으로 빼지 않고, **선택지 목록의 마지막 항목**으로
  통합한다. 다른 후보 버튼과 동일한 방식(탭 = 선택)으로 동작 — `onVote(null)`.
- 헤더 줄에 타이머 유지, 우측 화살표(▼/▲)로 접기 가능.

#### 상태 전이 규칙

| 트리거 | 결과 |
| --- | --- |
| 토론 단계 진입, 투표 가능 상태가 됨 | **자동으로 펼쳐짐** — "투표가 시작됐다"는 신호를 겸함 |
| 내가 투표를 완료함(`myVote !== null`이 됨) | **자동으로 접힘** — 채팅 입력을 다시 가리지 않게 |
| 접힌 상태에서 바를 탭 | 수동으로 펼침(투표 바꾸고 싶을 때) |
| 펼친 상태에서 ▲/헤더를 탭 | 수동으로 접음 |
| 라운드가 바뀌어 재투표 국면 진입(동점 재투표 등) | 다시 자동 펼침 — 매 투표 국면마다 위 규칙 반복 |

수동 토글은 자동 규칙을 덮어쓰는 임시 오버라이드로 취급한다 — 예를 들어 투표 후
자동으로 접혔어도 사용자가 다시 탭해서 펼쳐 볼 수 있고, 그 상태에서 재투표하면 다시
자동 접힘 규칙이 적용된다.

### ④ 채팅 입력창

`Chat.tsx`의 `locked` prop 그대로 사용. 투표 바가 접혀 있을 때만 입력창이 완전히
드러나는 게 이 구조의 목적이므로, 투표 바 펼침 상태에선 입력창이 화면 밖으로 밀리는 게
아니라 채팅 로그 영역이 줄어드는 쪽으로 흡수되어야 한다(③이 늘어난 만큼 ②가 줄어듦).

## 3. 시스템 이벤트 토스트 / 오버레이

큰 삽화나 결과 발표("A님이 살아남았습니다" 류)는 채팅 로그에 영구 삽입하지 않는다.

- 화면 전체 위에 뜨는 오버레이(스크림 + 카드 또는 배너)로 표시.
- 일정 시간 후 자동으로 사라지거나, 탭하면 바로 닫힘.
- 떠 있는 동안에도 레이아웃(①~④)은 그대로 유지 — 오버레이가 사라진 뒤 채팅/투표 상태가
  갑자기 밀리거나 하지 않는다.
- 시스템 메시지 자체(텍스트)는 지금처럼 채팅 로그에도 남는다(배경 띠 스타일) — 오버레이는
  "지금 막 일어난 일"을 강조하는 연출이고, 채팅 로그의 시스템 메시지는 그 일이 있었다는
  영구 기록이라는 역할 분담.

## 5. 아직 안 정한 것

- **브레이크포인트 기준폭** — 몇 px 이하에서 이 모바일 레이아웃으로 전환할지. 지금
  `game.css`엔 미디어쿼리가 아예 없다(기존 코드 확인함, 데스크톱 좌우 배치만 존재).
- **S4 `LifeVote.tsx`도 같은 접이식이 필요한가** — 지금 "죽인다 X / 살린다 Y" 한 줄
  요약형이라 이미 짧다. 접이식 없이 하단 고정 바 하나로 충분할 수도 있음 — 별도 판단 필요.
- 접힌 바에서 후보가 여러 명이라 한 줄에 다 안 들어갈 때(예: 5명 다 표를 받은 경우)
  줄바꿈할지, 가로 스크롤을 줄지, 상위 N명만 보여줄지 — 디자인 결정 필요.
- 토스트 노출 시간(몇 초), 스킵 가능 여부 — 결과 발표처럼 다 같이 봐야 하는 순간은
  스킵 막아야 할 수도 있음.
