# 봇 마피아 — wolfcha 활용방안

> wolfcha 소스 분석 결과를 봇 마피아 프로젝트에 어떻게 쓸 것인가
> `wolfcha-소스분석.md`와 함께 사용. 기획서·인수인계의 확정사항은 전제로 두고 작성했다

- **작성일**: 2026-07-30
- **대상 프로젝트**: 봇과 함께하는 마피아 (4주 / 4명 / 무료 API 티어)
- **전제**: 인수인계 §4 확정사항, §5 기각목록을 뒤집지 않는다

---

## 0. 판정

**이식 대상 6개, 폐기 대상 4개.**

wolfcha에서 가져올 것은 **컨텍스트 조립 계층 하나**이며, 아키텍처·상태관리·스택은 전부 버린다. 이식 대상은 전부 **단일 파일 수준의 유틸 또는 타입 정의**라서 스택 차이(Next.js vs Vite)의 영향을 받지 않는다.

가장 가치 있는 항목은 **사적 지식 격리(리스크 #7 대응)**와 **성격 프로파일 필드 목록(미결 #5)**이다. 이 둘만 가져와도 각각 2~3일치 시행착오를 아낀다.

## 1. 이식 항목 6개

### 🥇 이식 1 — 사적 지식의 target/outcome 이중 게이팅

| | |
|---|---|
| **대응 항목** | 기획서 5.5(사적 지식 격리), 리스크 #7(사적 지식 유출), 2주차 자동 테스트 |
| **출처** | `src/lib/prompt-utils.ts` → `buildRolePrivateInfo()` |
| **배치** | **2주차** (자동 테스트와 함께) |
| **작업량** | 반나절 |

**무엇을**

기획서 5.5의 격리 표는 역할별로 "아는 것"만 나눈다. wolfcha는 여기에 축을 하나 더 넣는다.

> **대상(누굴 지목했나)을 아는 것과 결과(그게 통했나)를 아는 것은 별개의 권한이다.**

**봇 마피아에 어떻게 적용되나**

| 역할 | 대상 (밤에 즉시 앎) | 결과 (아침 발표 전까지 모름) |
|---|---|---|
| 마피아 | 동료가 누구인지, 누굴 지목했는지 | **그 사람이 실제로 죽었는지** (의사가 막았을 수 있음) |
| 의사 | 누굴 보호했는지 | **보호가 통했는지** (애초에 마피아 표적이 아니었을 수 있음) |
| 시민 | — | — |

**왜 중요한가**

이걸 놓치면 의사 봇이 밤 결과를 아는 것처럼 말한다. 그건 **게임 버그이자 즉각적인 봇 티**다. 리스크 #7(사적 지식 유출)과 리스크 #5(봇이 너무 쉽게 들킴)가 동시에 터지는 지점이다.

**바꿔야 할 점**

wolfcha의 마녀 처리는 봇 마피아에 대응 역할이 없다(4역할 고정, 인수인계 §5). 수호(Guard) → 의사(Doctor) 매핑만 가져오면 된다. 단, wolfcha의 "수호는 연속 같은 대상 불가" 제약은 봇 마피아 규칙에 없으므로 빼야 한다.

**2주차 자동 테스트 케이스로 직행**

```
[ ] 시민 봇 컨텍스트에 마피아 동료 정보가 없는가
[ ] 시민 봇 컨텍스트에 밤 지목 대상이 없는가
[ ] 의사 봇 컨텍스트에 "보호 성공/실패"가 아침 발표 전에는 없는가
[ ] 마피아 봇 컨텍스트에 "지목 성공/실패"가 아침 발표 전에는 없는가
[ ] 사망자 채널 메시지가 생존자 봇 컨텍스트에 섞이지 않는가
[ ] 사망한 봇의 사적 지식이 다른 봇에게 승계되지 않는가
```

### 🥇 이식 2 — Persona / PlayerMind 필드 목록

| | |
|---|---|
| **대응 항목** | 미결 #5(성격 프로파일 6종 프롬프트 문안), 기획서 5.1 |
| **출처** | `src/types/game.ts` → `interface Persona`, `interface PlayerMind` |
| **배치** | **1주차 후반 ~ 2주차 초** |
| **작업량** | 필드 확정 반나절 + 6종 문안 작성 1~2일 |

**무엇을**

기획서 5.1의 성격 표는 `특징` + `발화빈도` + `말투규칙(문장길이/오타/초성/존댓말/이모티콘)` 정도다. wolfcha는 26개 필드로 쪼갠다.

**채택 권장 필드 (기획서 부록 A와 직접 대응)**

| 필드 | 대응하는 봇 티 | 채택 |
|---|---|---|
| `mistakePattern` | 논리가 과잉 | ✅ 필수 |
| `memoryBias` | **기억이 너무 정확** | ✅ 필수 |
| `speechLengthHabit` | 말수가 균일 | ✅ 필수 |
| `vocabularyStyle` + `voiceRules` | 문체가 너무 완결됨 | ✅ 필수 |
| `pressureStyle` | (압박 시 반응 — 봇 티가 가장 잘 드러나는 순간) | ✅ 필수 |
| `uncertaintyStyle` | (불확실할 때 — "그냥 느낌인데") | ✅ 필수 |
| `reasoningStyle`, `logicDepth` | 논리 과잉 보조 | ⭕ 권장 |
| `suspicionThreshold`, `courage` | 발언욕구 계수와 연동 가능 | ⭕ 권장 |
| `wolfDeceptionStyle` | 마피아일 때 기만 방식 | ⭕ 권장 (확정사항 4.1 이중목표와 직결) |
| `mbti`, `gender`, `age`, `relationships`, `voiceId`, `werewolfExperience` | — | ❌ 불필요 (TTS 기각, 관계망 범위 밖) |

**직접 만들어야 하는 필드 2개**

부록 A의 아래 두 항목은 **wolfcha에 대응 필드가 없다.** 봇 마피아의 고유 기여 영역이다.

| 봇 티 | 필요한 것 | 비고 |
|---|---|---|
| **뒤끝이 없음** | `grudgeMemory` — 나를 의심한 사람에 대한 감정 잔존 파라미터 | 라운드 간 상태 유지 필요 |
| **침묵을 못 견딤** | `silenceTolerance` — 말하지 않기로 선택할 확률 | **동기식에서는 발생조차 않는 문제.** 비동기 차별점과 직결 |

> `silenceTolerance`는 발언욕구 점수(확정사항 4.3)의 임계값에 곱해지는 계수로 구현하면 자연스럽다. 별도 LLM 호출 없이 해결된다.

**바꿔야 할 점**

- wolfcha 문안은 전부 중국어다. **구조는 이식되지만 문체 규칙은 이식되지 않는다.** 초성·오타·문장 끊기는 한국어 고유 신호이므로 직접 작성해야 한다
- 필드를 그대로 복사하면 *wolfcha가 세운 가설*을 검증하게 된다. 부록 A와 대조해 **겹치는 것만 채택**할 것

**숨은 섹션 처리도 함께 가져올 것**

성격 필드는 `<hidden_profile>` 블록으로 감싸 "이건 네 숨은 성향이니 직접 언급하지 마라"로 전달한다. 이게 없으면 봇이 "저는 신중한 편이라서요"라고 말해버린다 — 명백한 봇 티다.

### 🥈 이식 3 — fetchWithRetry (Retry-After 우선 + 지터)

| | |
|---|---|
| **대응 항목** | 기획서 7.6(방어적 구현), 1주차 LLM 프록시 |
| **출처** | `src/lib/llm.ts` → `fetchWithRetry()` |
| **배치** | **1주차** |
| **작업량** | 1~2시간 (약 40줄) |

**무엇을**

```ts
const RETRYABLE_STATUS = new Set([429, 500, 502, 503, 504]);

const base = response.status === 429 ? 1000 : 400;
const backoffMs = (retryAfterMs !== null
  ? Math.min(15000, Math.max(0, retryAfterMs))   // ① 헤더 우선
  : base * 2 ** (attempt - 1)) + jitter;          // ② 지터
```

**기획서 7.6보다 나은 점 2가지**

1. **`Retry-After` 헤더 우선 존중** — 제공자가 명시한 대기 시간을 쓴다. 무조건 1s,2s,4s,8s로 기다리는 것보다 성공률이 높다
2. **지터 추가** — 봇 4개가 동시에 429를 맞고 동시에 재시도하는 몰림 현상을 방지. 무료 티어에서 실제로 발생한다

**직접 만들어야 하는 것 (wolfcha에 없음)**

| 항목 | 기획서 근거 |
|---|---|
| 제공자 폴백 체인 (A 실패 → B 재시도) | 7.6 |
| 전 제공자 실패 시 규칙 기반 더미 발언 | 7.6 |
| 파일 캐싱 (동일 입력 해시 → 저장된 응답) | 7.4 |

wolfcha는 유료 게이트웨이 전제라 이것들이 없다. **무료 티어 전제인 봇 마피아에서는 오히려 차별 포인트**이므로 발표에서 언급할 가치가 있다.

**주의**: wolfcha의 배치 API(`{requests:[...]}`, 최대 12개)는 서버에서 `Promise.all`로 병렬 처리할 뿐 **상위 제공자 호출 횟수를 줄이지 않는다.** RPM 대책으로 오해하지 말 것. 왕복 지연만 줄인다.

### 🥈 이식 4 — FlowToken 패턴

| | |
|---|---|
| **대응 항목** | 기획서 5.4(재고 로직) |
| **출처** | `src/lib/game-flow-controller.ts` (AsyncFlowController 클래스 약 50줄) |
| **배치** | **2주차** (타이핑 위장 + 재고 로직과 함께) |
| **작업량** | 1시간 |

**무엇을**

```ts
export interface FlowToken {
  value: number;
  isValid: () => boolean;
}

export class AsyncFlowController {
  private tokenValue = 0;

  getToken(): FlowToken {
    const capturedValue = this.tokenValue;
    return {
      value: capturedValue,
      isValid: () => this.tokenValue === capturedValue,
    };
  }

  interrupt(): void { this.tokenValue += 1; }   // 상태가 크게 바뀌면 호출 → 기존 토큰 전부 무효화
}
```

같은 파일에 `pause()` / `resume()` / `waitForUnpause()`도 함께 들어 있다. 게임 일시정지 기능을 만들 계획이면 같이 가져오면 된다.

관례: **모든 `await` 직후 `token.isValid()`를 확인하고, false면 즉시 중단.**

**왜 봇 마피아에 더 중요한가**

기획서 5.4의 재고 로직이 정확히 이 문제다.

> 생성 중 새 메시지 3개 이상 누적 → 폐기 후 재생성
> 생성 중 나를 직접 지목하는 메시지 도착 → 폐기 후 재생성

wolfcha는 턴제라 이 상황이 거의 발생하지 않는데도 이 패턴을 만들었다. **봇 마피아는 비동기라 훨씬 자주 터진다.** 이게 없으면 폐기했어야 할 응답이 채팅창에 그대로 뜬다 — 대화 맥락에 안 맞는 발언은 부록 A의 "대화 앵커링 실패"로 직결된다.

**바꿔야 할 점**

wolfcha는 토큰이 게임 전체에 1개(글로벌)다. 봇 마피아는 **봇마다 독립 토큰**이 필요하다. 봇 A의 재생성이 봇 B의 생성을 무효화하면 안 된다.

### 🥉 이식 5 — 앵글 주입 (buildPerspectiveHint)

| | |
|---|---|
| **대응 항목** | 확정사항 4.3(발언욕구 점수)의 **보완재** |
| **출처** | `src/lib/prompt-utils.ts` → `buildPerspectiveHint()` |
| **배치** | **2주차** (성격 프로파일 이후) |
| **작업량** | 반나절 |

**무엇을**

플레이어마다 다른 **분석 앵글**을 프롬프트에 주입한다. 출력 포맷을 강제하지 않으면서 발언 다양성을 만든다.

```
- 너는 N번에게 지목당했다 → 대응할지 판단하라
- 너는 첫 발언자다 → 참고할 게 없으니 초기 판단을 던져라
- 어제 N번과 같은 표를 던졌다 → 언급할지 판단하라
```

**발언욕구 점수와의 관계 — 경쟁이 아니라 분업**

| | 결정하는 것 | 방식 |
|---|---|---|
| 발언욕구 점수 (4.3) | **누가** 말할까 | 로컬 규칙, LLM 없음 |
| 앵글 주입 (이식 5) | 말할 때 **무엇에 꽂혀 있을까** | 프롬프트 문자열, LLM 없음 |

**둘 다 LLM 호출 0회다.** 앵글 주입은 호출 예산에 영향을 주지 않으면서 발언 품질을 올린다. 확정사항 4.3을 훼손하지 않는다.

**보너스 — 발언욕구 계산식 재활용**

발언욕구 점수 계산에 쓰는 입력(지목당함, 직전 메시지가 나를 언급, 경과 시간)이 앵글 주입 입력과 **거의 동일하다.** 한 번 계산해서 두 곳에 쓰면 된다.

```
점수 계산 → 임계값 넘은 봇 선정 → 그 봇의 점수 구성요소를 앵글 문장으로 변환 → 프롬프트에 삽입
```

**필수 — 정보 누설 방어 로직도 함께 가져올 것**

wolfcha는 "인접 사망자" 앵글을 **밤 사망 공표 이전 페이즈에서 억제**한다. 안 그러면 앵글 문장 자체가 밤 결과를 누설한다. 봇 마피아도 앵글을 만들 때 **"이 문장이 그 봇이 몰라야 할 정보를 담고 있지 않은가"**를 반드시 검사해야 한다. 이식 1의 자동 테스트에 앵글 검사도 포함시킬 것.

**결정론적 시드**

wolfcha는 좌석번호 + 날짜를 시드로 쓴다. 봇 마피아는 리플레이 모드(확정사항 4.4)가 있으므로 **결정론이 필수**다. `Math.random()`을 쓰면 리플레이가 재현되지 않는다.

type Phase = "LOBBY" | "NIGHT_MAFIA" | "NIGHT_DOCTOR" | "DAY_DISCUSSION" | ...

## 2. 폐기 항목 4개

| 폐기 | 이유 |
|---|---|
| **아키텍처 전체** | Next.js App Router + Jotai. 봇 마피아는 Vite + Zustand + Socket.IO 서버 권위. **스택을 맞추려 하지 말 것** (인수인계 9.1에서 이미 판단함) |
| **클라이언트 권위 상태 구조** | wolfcha는 게임 상태 전부(전원 역할 포함)를 브라우저 localStorage에 저장. 솔로 게임이라 성립하는 설계. **봇 마피아는 사람이 여럿 들어오므로 따라가면 즉시 치팅 가능** |
| **명시적 캐싱 최적화** | `cache_control` / DeepSeek 프리픽스 캐싱. **Groq·Cerebras 무료 티어에는 이 기능이 없다.** 기획서 7.2의 절감분을 여기서 기대하지 말 것. Gemini는 암묵적 캐싱이 있으니 1주차 실측 때 확인 |
| **발언 순서 로직** | 좌석 순회 동기식. 봇 마피아 설계와 정면 배치. **참고할 것이 없음** |

### 기획서 4.2 (호출 예산) — 검증 결과

**40회 예산은 구조적으로 타당하다.**

wolfcha의 단가는 **AI 1명 × 1라운드당 2회**(발언 1 + 투표 1)다. 봇 마피아 계획도 봇 1명 × 1라운드당 2회다. **단가가 같다.** 총량 차이(wolfcha ~100회)는 인원(AI 8명 vs 봇 4명)과 경찰 선거 유무에서 온다.

> ⚠️ **단, 이 단가는 "1발언 = 1호출"이 지켜질 때만 성립한다.** wolfcha는 턴제라 폐기가 원천적으로 없어 공짜로 지켜진다. 봇 마피아는 비동기라 재생성이 발생한다. **확정사항 4.3(큐 직렬화)과 기획서 5.4(재생성 상한 5회)가 예산 전체를 떠받친다.**

**1주차 검증 항목에 추가:**

```
[ ] 1게임 총 호출 수 ≤ 40 인가
[ ] 그중 재생성으로 소모한 호출이 몇 회인가  ← 신규
[ ] 발언 큐가 실제로 직렬 처리되는가 (동시 생성 0건)  ← 신규
```

**코드를 직접 복사하는 경우 (이식 3, 4가 해당):**

1. 루트에 `NOTICE` 파일 생성
2. 내용: `본 프로젝트는 oil-oil/wolfcha (Apache-2.0)의 일부 유틸리티 구현을 참고/변형하여 사용합니다.`
