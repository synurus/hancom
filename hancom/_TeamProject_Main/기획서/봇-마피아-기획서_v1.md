# 봇과 함께하는 마피아 (Bot Mafia)

> 사람과 AI가 섞여 마피아 게임을 하고, 마지막에 **누가 봇이었는지** 지목하는 웹 게임

- **작성일**: 2026-07-29
- **기간**: 4주 (2026-07-27 ~ 2026-08-21 개발 / 09-08 발표)
- **인원**: 4명
- **분류**: 프론트엔드 팀 프로젝트
- **개발 환경**: 학원 PC (Intel UHD 630, 외장 GPU 없음) + 무료 API 티어

---

## 1. 한 줄 정의

사람과 봇이 섞인 마피아 게임. 게임이 끝나면 플레이어는 **누가 봇이었는지** 지목하고, 봇은 **지목당하지 않는 것**을 최우선 목표로 삼는다.

## 2. 기획 배경

LLM이 사람 흉내를 얼마나 낼 수 있는지에 대한 연구는 많지만, 대부분 **AI끼리만** 붙거나 **1:1 대화**다. 여러 사람과 여러 봇이 섞여 실시간으로 토론하는 환경은 거의 없다.

또한 기존 연구는 확인된 범위 내에서 전부 **동기식(순서대로 발언)** 구조다. 실제 마피아는 아무나 아무 때나 끼어드는 비동기 대화이고, **봇의 정체는 말의 내용보다 말하는 타이밍에서 먼저 드러난다.** 이 지점이 이 프로젝트의 핵심이다.

## 3. 핵심 설계 원칙

### 원칙 1 — 봇은 두 개의 정체를 동시에 숨긴다

봇의 목표는 우선순위가 있다.

1. **봇이라고 지목당하지 않을 것** (최우선)
2. 마피아 게임에서 승리할 것

그런데 이 둘은 **정면충돌한다.**

- 봇 티를 안 내려면 조용히 있는 게 안전하다 → 마피아에서 조용하면 의심받아 죽는다
- 마피아 역할이면 거짓말을 해야 한다 → 거짓말은 논리 파탄을 만들고, 파탄은 곧 봇 티다

이 충돌이 게임의 심장이며, 발표 첫 슬라이드에 놓을 문장이다.

### 원칙 2 — API 호출 예산이 설계 제약이다

무료 API 티어(분당 5~30회, 하루 100~1,500회)를 전제로 설계한다. "일단 만들고 나중에 최적화"는 이 프로젝트에서 통하지 않는다. **호출 횟수를 줄이는 설계가 곧 게임을 좋게 만드는 설계**여야 한다.

> **설계 목표: 1게임당 LLM 호출 40회 이하**

이 제약이 오히려 게임을 개선한다. 봇 전원이 매 턴 발언하면 호출이 폭발하는데, 그건 게임적으로도 나쁘다 — 사람들은 동시에 떠들지 않기 때문이다. **발언권 큐로 발화를 직렬화하는 것이 RPM 제어와 자연스러운 대화를 동시에 해결한다.**

## 4. 게임 규칙

### 구성

| 항목 | 값 |
|---|---|
| 총 인원 | 6명 |
| 사람 | 1~3명 (1인 모드가 기본) |
| 봇 | 3~5명 |
| 역할 | 마피아 2, 의사 1, 시민 3 |
| 라운드 | 최대 4일차 |

### 진행

1. **역할 배정** — 각자에게 개인 채널로 비공개 통보
2. **밤** — 마피아 살해 대상 선택, 의사 보호 대상 선택 (30초)
3. **낮 토론** — 자유 채팅 (라운드당 120초). **순서 없음. 아무나 끼어들 수 있음**
4. **투표** — 최다 득표자 추방 (30초)
5. 승패가 결정될 때까지 2~4 반복
6. **봇 지목 페이즈** — 살아있든 죽었든 모든 사람 플레이어가 각 참가자에 대해 "봇이다 / 사람이다"를 선택
7. **정체 공개** — 전원의 역할과 봇 여부 공개, 판별자 봇의 확률 예측 함께 표시

### 사망자 처리

사망자는 **관전 전용 채널**로 이동한다. 산 사람에게 정보를 흘릴 수 없다. 봇의 사적 지식 격리와 같은 문제이므로 설계를 한 번에 잡는다.

### 게임 중 의심 마킹

마지막에 한 번만 지목하면 진행 중 긴장이 없고 데이터도 한 점뿐이다. 플레이어는 **언제든 각 참가자에게 의심 마크를 켜고 끄고 바꿀 수 있으며**, 그 이력이 저장된다.

→ **"몇 라운드째에 정체가 드러났는가"** 라는 시계열 데이터가 생긴다. 발표용 그래프가 된다.

### 이중 점수

| 점수 | 대상 | 의미 |
|---|---|---|
| 승리 점수 | 사람·봇 공통 | 마피아 게임 승패 |
| 은폐 점수 | 봇 | 사람에게 봇으로 지목되지 않은 비율 |

두 점수를 분리해야 원칙 1의 충돌이 숫자로 드러난다. *"이 봇은 게임은 잘 이기는데 자꾸 들킨다"* 가 보인다.

## 5. 봇 설계

### 5.1 성격 프로파일

봇마다 다른 성격 프롬프트를 부여해 서로 다른 두뇌를 만든다. 초기 6종.

| 성격 | 특징 | 발화 빈도 |
|---|---|---|
| 주도형 | 토론을 이끌고 먼저 지목한다 | 높음 |
| 신중형 | 근거를 모아 뒤늦게 의견을 낸다 | 낮음 |
| 감정형 | 억울해하고 발끈한다. 뒤끝이 있다 | 중간 |
| 방관형 | 대세를 따르고 말수가 적다 | 매우 낮음 |
| 농담형 | 실없는 소리를 섞는다 | 높음 |
| 의심형 | 아무나 의심하고 자주 말을 바꾼다 | 중간 |

각 성격은 **말투 규칙**을 함께 갖는다. 문장 길이 분포, 오타 확률, 초성 사용 여부, 존댓말/반말, 이모티콘 빈도.

### 5.2 발언 타이밍 — LLM 호출 없이 결정

**이것이 프로젝트에서 가장 어렵고 가장 프론트엔드다운 부분이다.**

새 메시지가 올라올 때마다 각 봇의 **발언 욕구 점수**를 로컬 규칙으로 계산한다. LLM은 개입하지 않는다.

```
발언욕구 =
    (내가 직접 지목당함        ? 100 : 0)
  + (직전 메시지가 나를 언급    ?  60 : 0)
  + (내 마지막 발언 후 경과초 × 성격계수)
  + (성격별 기본 발화욕 × 난수)
  - (최근 30초 내 내 발언 수 × 40)
  - (현재 생성 중인 봇이 있음   ?  50 : 0)
```

- 임계값을 넘은 봇 중 **최고 점수 1명만** 생성 큐에 진입
- 큐는 **직렬 처리** → 이것이 곧 RPM 제어 장치
- 사람이 활발히 대화 중이면 봇의 발언욕구를 전체적으로 낮춰 끼어들지 않게 함

### 5.3 타이핑 위장

```
표시 지연 = 성격별 기본지연(0.8~3.0초)
          + 문장 길이 × (0.15~0.35초/글자)
          + 난수 흔들림
```

생성이 먼저 끝나도 타이핑 인디케이터를 유지하다가 지연 후 표시한다. 반대로 생성이 느리면 인디케이터를 먼저 켜서 "생각 중"으로 보이게 한다. **응답이 빨라도 티가 나고 느려도 티가 난다.**

### 5.4 재고 로직

생성 중에 대화가 크게 바뀌면 만들던 답이 낡은 답이 된다.

- 생성 중 새 메시지 3개 이상 누적 → 폐기 후 재생성
- 생성 중 나를 직접 지목하는 메시지 도착 → 폐기 후 재생성
- **단, 재생성은 게임당 5회로 제한** (호출 예산)

### 5.5 사적 지식 격리

각 봇은 자기 역할에 해당하는 정보만 컨텍스트에 받는다.

| 봇 역할 | 아는 것 |
|---|---|
| 마피아 | 동료 마피아가 누구인지, 밤에 누구를 지목했는지 |
| 의사 | 자기가 누구를 보호했는지 |
| 시민 | 공개 정보만 |

**어떤 봇도 "누가 봇인지"는 모른다.** 봇끼리 서로를 사람으로 알고 플레이한다. 이것이 자연스러움의 핵심이고, 동시에 은폐 성능의 공정한 측정 조건이다.

## 6. 판별자 봇

게임을 관전하며 각 참가자가 봇일 확률을 계산한다.

```
A: 82%   ████████▏
B: 41%   ████
C: 15%   █▌
```

### 네 가지 역할

1. **데모 화면** — 확률 막대가 실시간으로 흔들리는 그림
2. **평가 지표** — 사람 없이도 봇 성능을 측정할 수 있음
3. **진화 신호** — 프롬프트 진화 루프의 적합도 함수
4. **AI의 사고 과정 시각화** — 판단 근거를 함께 출력해 표시

### 순환 참조 방지 (필수)

봇이 판별자를 속이도록 최적화되고 판별자도 LLM이면, **둘이 자기들끼리만 통하는 균형**에 빠질 수 있다. 판별자는 못 잡는데 사람은 3초 만에 알아채는 봇이 나오면 프로젝트가 무의미해진다.

**대응**

- 사람의 실제 지목 데이터로 판별자 프롬프트를 주기적으로 보정
- 판별자를 2개(서로 다른 제공자·프롬프트) 두고 평균
- **발표에서 판별자 점수와 사람 정답률을 반드시 나란히 표시.** 두 숫자가 벌어지면 그것 자체가 정직한 발견이다

### 호출 절약

판별자는 매 턴 호출하지 않는다. **게임당 2회** — 2라운드 종료 시 1회, 게임 종료 시 1회.

## 7. API 호출 예산 설계

### 7.1 1게임당 호출 내역

| 항목 | 횟수 | 비고 |
|---|---|---|
| 낮 토론 봇 발언 | 24 | 봇 4명 × 라운드 2발언 × 3라운드 |
| 투표 이유 | 0 | 발언에 통합 |
| 밤 행동 (마피아/의사) | 3 | 낮 요약 참조, 짧은 출력 |
| 재생성 | ≤5 | 상한 |
| 판별자 | 2 | 중간 1회, 종료 1회 |
| **합계** | **≈34** | 목표 40 이하 |

무료 티어 하루 1,000회 기준 → **하루 약 29게임.** 제공자 2~3곳에 분산하면 하루 60게임 이상 가능하다. 개발과 테스트에 충분하다.

### 7.2 토큰 절감 — TPM이 RPM보다 먼저 걸린다

전체 대화 로그를 매번 보내면 토큰이 폭발한다. **롤링 요약 구조**를 쓴다.

```
[게임 상태 요약]      약 150 토큰   생존자, 라운드, 투표 결과
[내 사적 지식]        약 100 토큰   역할, 동료, 밤 행동
[내 성격 프로파일]    약 200 토큰   말투 규칙 포함
[이전 라운드 롤링요약] 약 200 토큰   LLM 아닌 규칙 기반 생성
[최근 발언 15개]      약 600 토큰
─────────────────────────────
입력 목표             1,500 토큰 이하
출력 목표               100 토큰 이하 (짧게 말하게 강제)
```

출력을 짧게 강제하는 것은 비용뿐 아니라 **자연스러움에도 도움된다.** 봇 티의 대표적 원인이 "말이 너무 길고 논리가 과잉"이기 때문이다.

### 7.3 제공자 분산 — 제약이 이점이 되는 지점

봇마다 **다른 제공자·다른 모델**을 배정한다.

| 봇 | 제공자 | 부수 효과 |
|---|---|---|
| 봇 A | Google AI Studio (Gemini Flash) | |
| 봇 B | Groq (Llama) | 말투가 자연히 달라짐 |
| 봇 C | Cerebras | |
| 봇 D | OpenRouter 무료 슬롯 | |
| 판별자 | 별도 제공자 | 순환 참조 완화 |

RPM 한도를 나눠 쓰는 동시에, **"봇마다 다른 두뇌"라는 요구사항이 공짜로 충족된다.** 같은 프롬프트라도 모델이 다르면 말투가 다르다.

### 7.4 개발 중 호출 절약 (중요)

| 모드 | 용도 | 호출 |
|---|---|---|
| **모의 모드** | UI 개발 전용. 미리 녹음한 대사를 지연과 함께 재생 | 0회 |
| **리플레이 모드** | 저장된 게임 로그 재생 | 0회 |
| **실전 모드** | 실제 LLM 호출 | 정상 |

**시각화·UI 담당자는 모의 모드로 작업하므로 API를 거의 쓰지 않는다.** 4명이 각자 하루 200회씩 태우면 첫날에 한도가 끝난다. 이 3모드 구조를 1주차에 먼저 만든다.

추가로 **프록시 레벨 파일 캐싱** — 동일 입력 해시는 저장된 응답 재사용. 같은 시나리오 재테스트에 한도를 쓰지 않는다.

### 7.5 프롬프트 진화 루프

**"봇끼리 게임해서 인간티 향상"의 현실적 구현.** 모델 파인튜닝은 4주 안에 불가능하므로 명시적으로 배제한다.

```
1세대: 성격 프롬프트 6종
   ↓ 봇끼리 게임 5판씩
   ↓ 판별자 점수로 순위
   ↓ 하위 절반 폐기, 상위 절반을 LLM으로 변형·교배
2세대: 6종
   ↓ 반복
```

- **호출량**: 5세대 × 6후보 × 5판 × 34회 ≈ 5,100회
- **실행 위치**: 개인 PC(RTX 4090) 야간 배치 또는 무료 티어 분산 실행
- **왜 가능한가**: 진화 루프는 인터랙티브가 아니다. 저녁에 스크립트를 걸어두고 아침에 결과 프롬프트(수 KB)만 커밋하면 된다. **기계 시간만 쓰고 사람 시간은 쓰지 않는다.**
- **자원이 부족하면**: 3세대 × 4후보 × 3판으로 축소. 그래프는 여전히 그려지고, "자원 제약 안에서 이만큼 검증했다"로 발표한다

**기대 산출물**: 세대별 판별자 점수 그래프. *1세대는 85% 걸렸는데 5세대는 52%까지 내려갔다* — 이 한 장이 발표에서 가장 강한 그림이다.

### 7.6 방어적 구현

- **모델 문자열 하드코딩 금지.** 설정 파일로 분리하고 폴백 체인 구성. 무료 티어의 모델은 예고 없이 사라진다
- 429 오류에 지수 백오프 (1s, 2s, 4s, 8s)
- 모든 제공자 실패 시 → 해당 봇을 **규칙 기반 더미 발언**으로 대체하고 게임은 계속 진행
- API 키는 백엔드 프록시에만. 프론트엔드 노출 절대 금지 (학원 공용 PC)
- 무료 티어는 입력이 학습에 사용될 수 있으므로 개인정보를 넣지 않는다

```
[브라우저]
  채팅 UI / 의심 마킹 / 판별자 확률 패널
        │ WebSocket
        ▼
[게임 서버]

        │
        ├──▶ [LLM 프록시]
        │       컨텍스트 조립 → 제공자 라우팅 → 캐시 → 백오프 → 폴백
        │
        └──▶ [게임 로그 저장]
                  │
                  ├──▶ 리플레이 (LLM 0회)

```

## 9. 화면 구성

### 9.1 로비

- 인원 구성 선택 (사람 1~3 / 봇 3~5)
- **"이 게임에는 AI 참가자가 포함됩니다" 고지** — 필수
- 참가자는 익명 닉네임으로 표시. 사람인지 봇인지 알 수 없음

### 9.2 게임 화면 (핵심)

- 중앙: 실시간 채팅. 타이핑 인디케이터
- 좌측: 참가자 목록. 각자 옆에 **의심 마크 토글** (사람만 보임, 본인만 보임)
- 우측: 페이즈 타이머, 밤 행동 패널(해당 역할만)
- 하단: 투표 UI

### 9.3 봇 지목 페이즈

- 각 참가자에 대해 "봇 / 사람" 선택
- 확신도 슬라이더 (선택)

### 9.4 결과 화면

| 표시 항목 |
|---|
| 전원의 역할과 봇 여부 공개 |
| **내 정답률** vs **판별자 정답률** 나란히 |
| 각 봇의 은폐 성공률 |
| 의심 마킹 시계열 그래프 — 몇 라운드째에 들켰는가 |
| 판별자의 판단 근거 |
| **"봇을 지목한 이유" 자유 입력** ← 핵심 데이터 수집 |

### 9.5 리플레이 뷰어

- 타임라인 스크럽
- 봇 발언에 마우스를 올리면 당시 발언욕구 점수와 컨텍스트 표시
- LLM 호출 0회로 동작

### 9.6 통계 대시보드

- 누적 게임 수, 사람 평균 정답률, 성격별 은폐 성공률
- **봇 티 사유 분류 결과** ← 프로젝트의 실제 산출물
- 세대별 진화 그래프

## 15. 성공 기준

**필수**

- 사람 1명 + 봇 4명이 게임을 끝까지 완주
- 1게임 호출 40회 이하
- 사적 지식 유출 0건
- 사람의 봇 판별 정답률이 **100%도 0%도 아닐 것** (양 극단이면 게임이 성립하지 않음)

**목표**

- 다인 모드 (사람 2~3명)
- 판별자 확률 패널
- 봇 티 사유 20건 이상 수집 및 분류
- 진화 루프 3세대 이상

**여유 있을 때**

- 성격 프로파일 사용자 정의
- 게임 리플레이 공유 링크
- 판별자 정확도와 사람 정확도의 상관 분석

## 부록 A. 봇 티 목록 (초기 가설)

**이 목록을 실측 데이터로 검증하고 확장하는 것이 프로젝트의 실제 산출물이다.**

### 이미 알려진 것 (표면적, 해결 쉬움)

| 현상 | 대응 |
|---|---|
| 반응이 0.1초 만에 옴 | 타이핑 지연 |
| 말투가 항상 일정 | 성격 프로파일 |
| 감정 표현이 없음 | 감정형 성격, 뒤끝 파라미터 |
| 투표 패턴이 규칙적 | 성격별 투표 성향 + 난수 |

### 실제로 어려운 것 (이쪽이 본 게임)

| 현상 | 설명 |
|---|---|
| **문체가 너무 완결됨** | 봇은 문장을 끝까지 쓴다. 사람은 오타 내고, 초성 쓰고, 중간에 끊고, 이어서 또 쓴다 |
| **논리가 과잉** | 근거를 3개씩 나열한다. 사람은 "그냥 느낌인데"로 끝낸다 |
| **기억이 너무 정확** | 3라운드 전 발언을 정확히 인용하면 그게 오히려 티다. 사람은 잘못 기억한다 |
| **뒤끝이 없음** | 사람은 자기를 의심했던 사람에게 감정이 남는다. 봇은 매 턴 리셋된 것처럼 공평하다 |
| **말수가 균일** | 사람은 몰릴 때 말이 폭발하고 관심 없을 때 조용하다 |
| **대화 앵커링 실패** | 여러 명이 동시에 떠들 때 누구에게 답하는 건지 놓친다 |
| **침묵을 못 견딤** | 사람은 그냥 안 쓸 때가 있다. 봇은 무언가 말하려 한다 |

**측정 방법**: 결과 화면의 "봇을 지목한 이유" 자유 입력을 수집해 분류하고, 위 가설과 대조한다. 4주차 테스트 20판이면 60~100건의 사유가 모인다.

## 부록 C. 윤리 고지

- 로비와 게임 시작 화면에 **AI 참가자 포함 사실을 명시**
- 게임 종료 시 전원의 정체를 예외 없이 공개
- 수집한 대화 로그의 용도(봇 티 분석)를 사전 고지
- 이 게임의 목적은 **속임수 기술의 개발이 아니라 그 한계의 측정**임을 발표에서 명확히 할 것
