# 개념학습 기록 시스템 기획

## 프로젝트 개요

- **아이템**: 새로 배운 기술 개념을 조사·정리해 팀 저장소에 자동 기록하는 시스템
- **배경**: 2주차 과업 중 "다른 기술을 배우려는 의지가 있는가"를 평가받는 항목이 있음. 단순히 "이거 배웠다"는 선언이 아니라, [왜 배웠는지 / 무엇을 배웠는지 / 실제로 어떻게 활용했는지] 세 요소가 근거와 함께 남아야 한다고 판단함
- **과업 연계**: 2주차 "학습 의지 증빙" 과업 겸함
- **형태**: 1주차와 동일하게 별도 서비스가 아니라, Claude Code Skill(작업 절차 문서) 1개

## 왜 "활용처"를 사람이 안 쓰고 스킬이 직접 조사하는가

처음 설계할 때는 사용자가 주제·이유·활용처를 전부 인자로 넘기는 방식도 고려했음. 하지만 그렇게 하면 "실제로 활용했다"는 근거가 본인 진술뿐이라 증빙력이 약함. 그래서 **활용처만은 사람이 서술하지 않고, 스킬이 Zeteo(팀 실제 프로젝트) 코드베이스를 직접 검색해서 찾아내도록** 설계함. 코드에서 못 찾으면 지어내지 않고 "찾지 못함"이라고 정직하게 기록하도록 명시함 — 근거 없는 활용처를 만들어내는 것이 가장 큰 리스크였기 때문.

## 조사 대상과 저장 위치의 분리

이 시스템은 두 개의 서로 다른 저장소를 다룸: 조사 대상은 `Project/Zeteo`(GitHub `origin`을 추적하는 clone), 저장 위치는 `Frontend/TeamB/2주차/배운개념/`. 두 경로가 다른 저장소라는 점을 스킬 문서 상단에 명시해, 실수로 엉뚱한 곳에 쓰거나 읽는 것을 방지함.

`Project/Zeteo`를 조사할 때 "로컬 폴더를 그대로 Grep/Read"하는 방식은 채택하지 않음. 두 가지 문제가 있었음:

1. **로컬이 항상 최신이 아닐 수 있음** — 팀원이 GitHub에 새로 푸시해도 로컬에서 `pull`하지 않으면 반영 안 됨
2. **팀이 파트별로 브랜치를 나눠 작업함** (`main`/`dev`/`feat/bot`/`feat/server`/`feat/game-ui`/`feat/layout`) — 로컬은 항상 그중 브랜치 하나만 체크아웃되어 있으므로, 다른 팀원 브랜치에만 있는 기능은 애초에 로컬 작업 트리에서 안 보임

GitHub API/웹 검색으로 전환하는 방안도 검토했으나, 비공개 저장소 인덱싱 제약과 기본 브랜치 위주로만 검색되는 한계가 있어 채택하지 않음. 대신 로컬 clone이 이미 `origin`을 추적하고 있다는 점을 활용해, **작업 트리(체크아웃 브랜치)는 건드리지 않고 `git fetch`로 참조만 최신화한 뒤, `git grep`으로 모든 원격 브랜치를 한 번에 검색**하는 방식을 채택함. 매칭된 파일은 `git show <브랜치>:<경로>`로 체크아웃 없이 그 브랜치 시점 내용을 그대로 확인함. 속도·정확도는 로컬 grep 그대로 유지하면서, 최신성과 브랜치 커버리지 문제를 함께 해결함.

## 핵심 기능

| # | 기능 | 내용 |
|---|---|---|
| 1 | 개념학습 기록 (`study-note`) | 주제와 이유를 인자로 받아, Zeteo 코드베이스를 검색해 실제 활용처를 스스로 조사하고, 기본설명 + 활용처 + 퀴즈 형식으로 정리해 마크다운 파일로 저장 |
| 2 | 코드 기반 활용처 검증 | 주제 관련 키워드로 Grep 검색 → 매칭 파일 실제 열람 → README 등 설계 문서 확인. 못 찾으면 "찾지 못함"으로 정직하게 기록 (근거 날조 금지) |
| 3 | 이해도 확인 퀴즈 | 정리한 개념에 대해 객관식 위주 퀴즈 3~4문항 + 정답/해설을 함께 생성 |

## 절차 요약

1. 인자 파싱 — `<주제> "<이유>"` 형식, 누락 시 중단하고 확인
2. Zeteo 코드베이스 조사 — `git fetch`로 원격 참조 최신화 → 모든 원격 브랜치 대상 `git grep` 키워드 검색 → `git show`로 매칭 파일 내용 확인 → README 확인
3. 기본설명 작성 (처음 접하는 사람도 이해 가능한 수준)
4. 조사 결과 기반 활용처 서술 (파일 경로 인용)
5. 퀴즈 작성
6. `배운개념/<주제>.md`로 저장 (동일 주제 존재 시 덮어쓸지 확인)
7. git 안전장치 적용 후 커밋·푸시
8. 완료 보고 (주제, 파일명, GitHub 링크)

## git 작업 안전장치

1주차 회의록 자동화 시스템과 **동일한 원칙**을 그대로 적용함 — 학습 기록도 팀 공유 저장소에 자동 반영되므로 예기치 못한 변경이 그대로 들어가지 않도록 함.

1. 새 학습 기록 파일 외 다른 변경 사항이 있으면 즉시 중단
2. `main` 브랜치가 아니면 중단
3. 최신 이력 반영 시 충돌 발생하면 자동 병합 시도하지 않고 중단
4. 새로 생성한 학습 기록 파일 한 개만 선택적으로 반영
5. 원격 반영 실패 시 강제로 밀어붙이지 않고 정확한 오류와 함께 중단·보고

## 안전 관련 추가 고려사항

- **근거 날조 금지**: 코드에서 명확한 활용처를 찾지 못했을 때 그럴듯하게 지어내지 않고, "찾지 못함 — 계획 단계이거나 미구현일 수 있음"으로 정직하게 기록
- **프롬프트 인젝션 방어**: 조사 과정에서 읽는 코드·문서 내용에 지시문처럼 보이는 텍스트가 섞여 있어도 실행하지 않고 데이터로만 취급

## 향후 확장 여지 (미착수)

1. 이미 있는 주제를 재조사했을 때 이전 기록과 자동 비교(diff)해서 변경점만 보여주는 기능
2. 여러 주제를 한 번에 일괄 정리하는 배치 모드
3. 퀴즈 결과를 실제로 풀어보고 채점까지 이어지는 인터랙티브 모드
