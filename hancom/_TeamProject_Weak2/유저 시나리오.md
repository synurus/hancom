# 개념학습 기록 시스템 — 유저 시나리오

## 페르소나

**김정현** — Zeteo 프로젝트에서 봇·AI 파트(B)를 맡고 있음. 이번 주에 팀 채팅에서 실시간 통신 문제를 논의하다가 웹소켓 개념을 새로 공부하게 됨. 2주차 과업에 "다른 기술을 배우려는 의지" 항목이 있어, 그냥 배우고 끝내는 게 아니라 근거를 남겨야 하는 상황.

## 상황

이현우가 서버 파트에서 실시간 상태 동기화를 웹소켓으로 처리한다는 걸 알게 됨. 정현은 웹소켓을 개념으로만 알고 있었지 실제로 팀 프로젝트 어디에 어떻게 쓰이는지는 확인해본 적 없음. "안다"와 "우리 프로젝트에 어떻게 쓰였는지 설명할 수 있다"는 다르다고 느낌.

## 시나리오

1. 정현이 Claude Code에서 직접 입력함: `/study-note 웹소켓 "팀프로젝트 실시간 동기화에 쓰인다고 해서 개념부터 활용까지 확인하려고 배웠다"`
2. 스킬이 웹소켓 개념을 먼저 정리해줌 — 정현이 이미 알던 내용과 크게 다르지 않아 가볍게 훑고 넘어감
3. 스킬이 Zeteo 저장소 전체 브랜치를 뒤져서 실제로 웹소켓이 쓰인 파일을 찾아냄. 정현이 몰랐던 `feat/server` 브랜치의 코드였음 — 로컬에 체크아웃해둔 적도 없던 브랜치라, 직접 찾았으면 놓쳤을 부분
4. 활용처를 읽어보니 예상과 달리 이벤트 이름 규약(`action`/`event`)이 이미 정해져 있었다는 걸 알게 됨 — 개념 공부가 실제 우리 프로젝트 이해로 자연스럽게 이어짐
5. 퀴즈 3문항을 풀어보며 이해가 헷갈리던 부분(연결 유지 방식)을 스스로 확인함
6. 결과 파일이 `2주차/배운개념/웹소켓.md`로 저장되고, 자동으로 커밋·푸시까지 완료됨
7. 정현이 GitHub 링크를 열어 결과물을 최종 확인 — 이후 팀 채널에 필요하면 공유

## 얻는 것

- "배웠다"는 선언이 아니라, 왜 배웠는지·무엇을 배웠는지·실제 코드 어디에 쓰였는지가 파일 하나에 남음
- 활용처를 직접 안 써도 되니, 스스로도 몰랐던 팀원의 코드를 이 과정에서 발견하게 됨 (부수 효과지만 실질적으로 유용함)
- 한번 만들어두면 다음에 다른 개념(예: JWT, ORM)을 배울 때도 같은 절차를 그대로 반복 가능
