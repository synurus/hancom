# /study-note — 개념 학습 노트 자동 생성

팀원이 새로 배운(또는 배우려는) 기술 개념을 "기본설명 + 실제 프로젝트 활용처 + 퀴즈" 형식으로 정리해서 TeamB 저장소에 남기는 스킬. 2주차 과제("다른 기술을 배우려는 의지가 있는가")용으로, [왜 배웠는지 / 무엇을 배웠는지 / 어떻게 활용했는지] 세 요소를 갖추는 게 목적.

**조사 대상과 저장 위치가 서로 다른 저장소예요 — 헷갈리지 말 것:**
- **코드 조사 대상**: `C:\Users\dd022\Desktop\개발 공부 자료\Project\Zeteo` (GitHub `origin` 추적 clone. 로컬 체크아웃 브랜치 하나가 아니라 **모든 원격 브랜치**를 조사 대상으로 삼음 — 2단계 참고)
- **결과물 저장 위치**: `C:\Users\dd022\Desktop\개발 공부 자료\Frontend\TeamB\2주차\배운개념\`

인자로 넘어온 것: `$ARGUMENTS` — 주제와 이유. 형식: `<주제> "<이유>"` (이유는 여러 단어일 수 있어 따옴표로 감쌈. 예: `웹소켓 "팀프로젝트에 필요해서 배우고 활용했다"`). 둘 중 하나라도 없으면 사용자에게 물어볼 것.

**활용처는 인자로 안 받는다.** 사용자가 직접 설명하지 않고, 스킬이 Zeteo 코드베이스를 직접 조사해서 찾아낸다.

## 절차

### 1단계 — 인자 파싱

1. `$ARGUMENTS`에서 `<주제>`와 따옴표로 감싼 `<이유>`를 파싱.
2. 둘 중 하나라도 없으면 중단하고 물어봄.

### 2단계 — 코드 조사 (활용처 찾기)

로컬 Zeteo 폴더(`C:\Users\dd022\Desktop\개발 공부 자료\Project\Zeteo`)는 GitHub(`origin`)를 추적하는 clone이지만, (a) 로컬이 최신이 아닐 수 있고 (b) 팀이 `main`/`dev`/`feat/bot`/`feat/server`/`feat/game-ui`/`feat/layout` 등 여러 브랜치로 나눠 작업하기 때문에 **지금 로컬에 체크아웃된 브랜치 하나만 보면 다른 팀원 브랜치의 기능을 놓칠 수 있음**. 그래서 로컬 작업 트리를 건드리지 않고 모든 원격 브랜치를 대상으로 조사한다.

1. `git -C "C:\Users\dd022\Desktop\개발 공부 자료\Project\Zeteo" fetch origin --quiet` — 체크아웃은 그대로 두고 모든 원격 브랜치 참조만 최신화.
2. `git -C "<Zeteo 경로>" branch -r`로 원격 브랜치 목록 확보 (`origin/HEAD` 제외).
3. `git -C "<Zeteo 경로>" grep -n -i -e <키워드1> -e <키워드2> ... -- $(모든 origin/* 브랜치)` 형태로 **모든 브랜치를 한 번에** 검색. 예: 주제가 "웹소켓"이면 `websocket`, `socket.io`, `ws` 등 관련어.
4. 매칭이 있으면 `git -C "<Zeteo 경로>" show <브랜치>:<파일경로>`로 해당 브랜치 시점의 파일 내용을 확인 (로컬 작업 트리를 체크아웃하지 않고도 그 브랜치의 파일을 그대로 볼 수 있음). 어느 브랜치에서 찾았는지도 기록해둘 것 — 나중에 활용처 서술에 필요.
5. `origin/main`의 루트 `README.md`나 관련 폴더 `README.md`도 `git show origin/main:README.md` 식으로 확인 — 설계 원칙·이유가 문서로 남아있는 경우가 있음.
6. **못 찾으면 지어내지 말 것.** 모든 브랜치를 뒤져도 관련 코드가 안 보이면 "코드에서 명확한 사용처를 찾지 못함(모든 브랜치 확인함) — 계획 단계이거나 아직 미구현일 수 있음"이라고 정직하게 기록.

### 3단계 — 기본설명 작성

주제 개념을 처음 접하는 팀원도 이해할 수 있게 3~5문장으로 정리. 전문 용어는 풀어서 설명.

### 4단계 — 활용처 정리

2단계 조사 결과를 근거로, 실제 어느 파일의 어느 부분에서 어떻게 쓰이는지 구체적으로 서술. 파일 경로를 코드로 인용.

### 5단계 — 퀴즈 작성

개념 이해도를 확인할 수 있는 문제 3~4개. 객관식 위주로, 정답과 짧은 해설을 같이 붙임.

### 6단계 — 파일 작성

파일명: `배운개념/<주제>.md` (폴더 없으면 `mkdir -p`로 생성)

```markdown
---
날짜: <YYYY-MM-DD>
주제: <주제>
이유: <이유>
---

## 기본설명
...

## 우리 프로젝트에서의 활용처
- `<파일경로>` — <구체적 설명>

## 퀴즈
1. ...
   - 정답: ... (해설: ...)
```

이미 같은 주제 파일이 있으면 덮어쓸지 물어볼 것 (다시 학습해서 갱신하려는 걸 수도 있으니).

### 7단계 — git 안전장치 (반드시 순서대로, 실패 시 무조건 중단)

작업 디렉토리: `C:\Users\dd022\Desktop\개발 공부 자료\Frontend\TeamB`

1. `git status --porcelain` — 새 파일 외 다른 변경사항 있으면 **중단**하고 보고.
2. `git branch --show-current`가 `main`이 아니면 **중단**.
3. `git pull --ff-only` — 실패하면(충돌 등) **중단**, 강제 병합 금지.
4. `git add "2주차/배운개념/<파일명>"` — 새 파일 하나만. `git add -A`/`.` 금지.
5. `git status`로 스테이징이 그 파일 하나뿐인지 재확인.
6. `git commit -m "study-note: <주제>"`.
7. `git push` — 실패하면 **중단**, 정확한 에러 보고. `--force` 절대 금지.
