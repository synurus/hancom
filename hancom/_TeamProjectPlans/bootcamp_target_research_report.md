### 🎯 Target 1. 50~60대 / 은퇴 실버 (5060 & Retired Silver)

#### 1) Pain Point 재확인 (근거 기반)
* **통계 및 조사 근거**:
  * **디지털 정보격차**: 한국지능정보사회진흥원(NIA)의 [2025/2026 디지털정보격차 실태조사](https://www.nia.or.kr)에 따르면, 4대 정보취약계층 중 고령층의 **디지털 역량 수준은 일반 국민 대비 65.9%**로 최하위권입니다. 특히 생성형 AI 서비스 경험률은 일반 국민(59.4%) 대비 취약계층(**31.9%**)에서 심각한 격차를 보입니다.
  * **재취업 욕구와 현실**: 통계청 [2024~2025년 경제활동인구조사 고령층 부가조사](https://kosis.kr)에 따르면 55~79세 고령층 인구 중 **69.4%가 계속 일하기를 희망**하며, 주요 사유는 '생활비 보탬(55.2%)' 및 '일하는 즐거움(35.8%)'입니다. 그러나 실제 구직 과정에서 워크넷, 고용24 등 디지털 폼 접수와 본인인증 절차에서 심각한 진입장벽을 겪습니다.
* **커뮤니티 발화 현황**:
  * 네이버 카페 ('5060 재취업 세상', '은퇴후 50년'): *"정부 지원 시니어 일자리 공고를 봐도 지원서 서류 첨부나 본인인증 단계에서 화면이 넘어가질 않아 결국 자녀에게 매번 부탁하거나 포기한다."*, *"키오스크나 무인 민원 발급기 터치 폰트가 너무 작고 메뉴 구조가 복잡해 뒤 사람 눈치가 보인다."*

#### 2) 핵심 AI 기능 설계 (AI 필수성)
* **기능 1: 시니어 맞춤 대화형 공공/구직 행정 폼 자동 작성 에이전트**
  * 복잡한 정부24/고용24 구직 신청 폼을 시니어 눈높이에 맞춘 대화형 음성 인터페이스(STT/TTS)로 전환. "무슨 일을 해오셨나요?"라는 질문에 시니어가 자유롭게 말하면, AI가 규격화된 행정 이력서 항목으로 변환·입력.
* **기능 2: 음성 기반 자서전형 이력서 & 경력 재구성기**
  * 5060 은퇴자의 비정형 구술 경력(예: "내가 20년 동안 공장에서 자재 관리하고 트럭 운전했지")을 현대 직무 키워드(예: "물류 자재 관리 및 운송 라이선스 보유")로 AI가 재구성.
* 🛠️ **AI 필수성**: 5060세대의 구술형 비정형 음성 데이터를 행정 표준 데이터로 매핑하는 작업은 단순 규칙(Rule-based) 알고리즘으로는 불가능하며, 자연어 이해(NLU) 및 멀티모달 LLM이 필수입니다.

#### 3) 기술 아키텍처 초안 & 데이터 소스
* **Tech Stack**: React / Next.js (고대비 폰트 UI), Node.js / Python FastAPI, OpenAI Whisper / Naver CLOVA Speech API, LangChain Agent.
* **데이터 소스**:
  * [공공데이터포털(data.go.kr)](https://www.data.go.kr) `고용노동부 고용24 일자리 정보 API`
  * `보건복지부 복지위로금/노인일자리 지원 사업 API`
  * [미검증 API]: *일부 지자체 노인 복지관 자체 DB 구축 API는 존재 여부 미검증*

#### 4) 4주 MVP 스코프 (4인 개발자, 3~4주)
* **1주차**: 고용24 공공 API 연동 및 STT/TTS 음성 처리 파이프라인 구축
* **2주차**: 대화형 구직 폼 에이전트 & 이력서 키워드 추출 LLM 프롬프트 개발
* **3주차**: 시니어 특화 고대비/초대형 UI 및 간단한 카카오 알림톡/PDF 생성 파이프라인 결합
* **4주차**: 실사용자(5060 대역 테스트) UX 검증 및 서류 제출 모의 파이프라인 완성

#### 5) 경쟁/차별화 + 리스크
* **기존 서비스**: 시니어톡톡, 똑똑관보, 노인일자리여기.
  * **차별점**: 기존 서비스는 단순 일자리 목록 조회에 그치나, 본 아이템은 음성 인터페이스 기반의 **'자동 작성 에이전트'** 역할을 수행.
* **법적/윤리적 리스크**:
  * **본인인증 벽**: 공공기관 실제 대리 접수 시 PASS/공동인증서 API 활용 법적 제한.
  * **개인정보보호법**: 주민등록번호, 민감 경력 정보 수집에 따른 법적 규제 준수 필요.

### 🎯 Target 2. 바이브코더 (Vibe Coder - AI 활용 개발자)

#### 1) Pain Point 재확인 (근거 기반)
* **통계 및 조사 근거**:
  * **AI 도구 사용 현황과 한계**: Snyk의 [2024 AI Code Security Report](https://snyk.io) 및 Retool의 [2024 State of AI in Software Engineering](https://retool.com)에 따르면 개발자의 **75% 이상이 AI 코드 생성 도구를 활용**하고 있으나, AI가 생성한 코드의 아키텍처 비일치 및 엣지 케이스 오류로 인해 **디버깅 시간이 오히려 늘어나는 현상**이 보고됨.
  * **Context Window 소진과 Code Drift**: AI가 전체 코드베이스의 아키텍처 컨벤션(예: 디렉토리 구조, 상태 관리 패러다임)을 기억하지 못해 불필요한 코드 중복, 사용 중단된(Deprecated) API 재사용, 의존성 충돌을 일으킴.
* **커뮤니티 발화 현황**:
  * Reddit (r/Cursor, r/ChatGPTCoding, Hacker News): *"AI로 코드 짤 때 처음엔 속도가 10배 빠른데, 코드베이스가 커지면 한 곳 고치다 기존 기능 2개가 작살나는 'Doom Loop'에 빠진다."*, *"Cursor나 Bolt.new가 만들어준 코드가 동작은 하는데 아키텍처가 엉망진창이라 나중에 리팩토링이 불가능한 기술부채 덩어리가 된다."*

#### 2) 핵심 AI 기능 설계 (AI 필수성)
* **기능 1: AST & Git Diff 기반 AI 아키텍처 드레프트(Drift) 방지 에이전트**
  * Vibe Coder가 프롬프트로 코드를 대량 생성할 때, AST(Abstract Syntax Tree)와 Git Diff를 실시간 분석하여 프로젝트의 아키텍처 규칙(예: Clean Architecture 규칙, 특정 라이브러리 wrapping 규칙)을 위반하는지 AI가 자동 감지 및 교정 디렉티브 제공.
* **기능 2: AI Dynamic Test Harness & Integration Mock Generator**
  * Vibe Coder가 수동으로 브라우저를 눌러보지 않아도 되도록, 생성된 기능/API에 대한 Edge Case 단위 및 통합 테스트 코드(Jest/Playwright)와 Mock 서버를 실시간 자동 생성하고 Isolated Sandbox에서 자동 실행하여 결과를 보고.
* 🛠️ **AI 필수성**: 개발자의 자연어 의도와 코드 변경분의 수평적 구조(AST), 엣지 케이스 경계값 예측은 정적 분석 툴(ESLint 등)로는 불가능하며, Code-specialized LLM(Claude 3.5 Sonnet / DeepSeek-Coder)과 AST 연동 없이는 성립 불가능합니다.

#### 3) 기술 아키텍처 초안 & 데이터 소스
* **Tech Stack**: Tree-sitter (AST 분석 파서), Node.js / TypeScript, Docker / WebContainers (테스트 격리 실행), GitHub REST/GraphQL API, Claude 3.5 Sonnet / DeepSeek API.
* **데이터 소스**:
  * 대상 프로젝트의 Git Repository & Codebase AST.
  * Language Server Protocol(LSP) 정적 파싱 데이터.

#### 4) 4주 MVP 스코프 (4인 개발자, 3~4주)
* **1주차**: Git Diff 추적 및 Tree-sitter 기반 AST 파싱 엔진 구축
* **2주차**: 아키텍처 컨벤션 검증 및 테스트 코드 생성 LLM 프롬프트 파이프라인 구축
* **3주차**: Isolated Docker/WebContainer 기반 자동 테스트 실행기 및 결과 웹 대시보드 구축
* **4주차**: 실제 Vibe Coding 프로젝트(Cursor/Bolt.new 생성 코드) 적용 도그푸딩 및 UX 개선

#### 5) 경쟁/차별화 + 리스크
* **기존 서비스**: CodeRabbit, Qodo (CodiumAI), Sweep.dev.
  * **차별점**: 기존 도구는 단순 PR 리뷰나 단일 함수 Unit Test 생성에 치중하나, 본 아이템은 **Vibe Coding 특화 "Architecture Drift 감지 + 동적 테스트 Execution"**에 집중.
* **법적/윤리적 리스크**:
  * **코드 라이선스 오염**: AI가 학습/참고한 오픈소스 라이선스(GPL 등) 저작권 이슈.
  * **보안 취약점**: AI가 생성한 테스트 케이스의 환각(Hallucination)으로 인한 취약점 간과 가능성.

### 🎯 Target 3. 강사 (Instructors / Teachers - 온/오프라인, 학원, 학교)

#### 1) Pain Point 재확인 (근거 기반)
* **통계 및 조사 근거**:
  * **행정 및 수업 외 과중한 업무**: OECD의 [TALIS 2024 (Teaching and Learning International Survey)](https://www.oecd.org) 보도자료에 따르면, 한국 교사의 주당 일반 행정업무 시간은 **중등 6.0시간(OECD 1위, 평균 3.0시간의 2배)**, **초등 4.5시간**에 달합니다. 교사의 76%가 번아웃을 경험하며, 문제 출제 및 평가 계획서 작성 스트레스가 상당합니다.
  * **학원 강사의 변형 문제 및 피드백 부담**: 네이버 카페 '강사모'(강사들의 모임) 실태 조사 및 게시글 분석에 따르면, 학원 강사의 하루 평균 업무 시간 중 **2~3시간이 학생별 변형 문제 제작, 오답 워크시트 편집, 학부모 상담 카톡/리포트 작성**에 소비됩니다.
* **커뮤니티 발화 현황**:
  * 네이버 카페 ('강사모', '초아모'): *"학생마다 틀리는 문제 유형이 다 달라서 변형 문제 만들어주고 오답 노정 정리해 주는 데 매일 밤을 새운다."*, *"학부모 상담 리포트를 매주 써서 보내야 하는데, 똑같은 멘트 쓸 수 없어 작성하는 데 엄청난 피로감을 느낀다."*

#### 2) 핵심 AI 기능 설계 (AI 필수성)
* **기능 1: 손글씨/풀이 OCR 기반 오개념 진단 & 개인화 변형 문제지 파이프라인**
  * 학생이 푼 시험지/오답 풀이 사진을 업로드하면 Vision OCR로 수식과 손글씨를 인식. AI가 학생의 오개념 단계(예: "이차방정식 근의 공식 부호 착오")를 진단하고, 동일 개념의 맞춤형 난이도 변형 문제를 자동 생성하여 인쇄용 PDF 문제지로 변환.
* **기능 2: 주간 성취도 데이터 기반 학부모 1:1 맞춤 상담 리포트 에이전트**
  * 강사가 입력한 단문 메모("오늘 집중력 부족, 3번 유형 반복 틀림")와 퀴즈 점수 데이터를 결합하여, 학부모 성향(친절형/팩트중심형)에 맞춘 전문적인 주간 성취도 보고서 텍스트 및 카드뉴스 이미지 생성.
* 🛠️ **AI 필수성**: 손글씨 풀이의 오개념 유형 파악, 유사 변형 문제의 문맥 유지 생성, 학부모 톤앤매너 상담 텍스트 변환은 정적 규칙 알고리즘으로 불가능하며, Vision LLM과 교육용 RAG 파이프라인이 핵심입니다.

#### 3) 기술 아키텍처 초안 & 데이터 소스
* **Tech Stack**: Python FastAPI, Mathpix API / Google Cloud Vision OCR / CLOVA OCR, OpenAI GPT-4o / Claude 3.5 Sonnet, Vector DB (Chroma/Pinecone), React / Next.js.
* **데이터 소스**:
  * [AIHub](https://www.aihub.or.kr) `한국어 교육/수학/국어 문제 데이터셋`
  * open-source math dataset (GSM8K 등) 및 변형 문제 템플릿 DB.
  * [미검증 API]: *시중 출판사(개념원리, 쎈 등) 문제 은행 Open API는 존재하지 않음 (저작권 문제로 미검증/부재).*

#### 4) 4주 MVP 스코프 (4인 개발자, 3~4주)
* **1주차**: Mathpix/Vision OCR 연동 및 손글씨 풀이 파싱 모듈 개발
* **2주차**: 오개념 진단 RAG 엔진 및 변형 문제 생성 프롬프트 구축
* **3주차**: 학부모 맞춤 상담 리포트 생성기 및 PDF 문제지 레이아웃 렌더링 파이프라인 개발
* **4주차**: 강사용 웹 대시보드 인터페이스 완성 및 현직 강사 피드백 반영

#### 5) 경쟁/차별화 + 리스크
* **기존 서비스**: 매쓰플랫(Math Flat), 콴다(Qanda), Riiid, Classting.
  * **차별점**: 매쓰플랫 등은 고가의 B2B 수학 전용 문제은행 솔루션임. 본 아이템은 **"손글씨 오개념 파악 + 학부모 피드백 통합 Copilot"**으로 과목 중립적이고 경량화된 SaaS를 지향.
* **법적/윤리적 리스크**:
  * **개인정보보호법**: 미성년 학생 성적, 이름, 사진 데이터 처리에 대한 법정 대리인 동의 이슈.
  * **저작권 리스크**: 시중 교재 문제를 직접 스캔하여 사용 시 저작권법 위반 리스크. (AI로 완벽 재창작/변형 필요).
  * **AI 환각 리스크**: 잘못된 정답 또는 해설 생성 시 강사의 신뢰도 타격.

### 🏆 최종 추천: **Target 2. 바이브코더 (Vibe Coder)**

#### 💡 핵심 추천 근거 3가지

1. **압도적인 유저 접근성과 빠른 데일리 피드백 (Dogfooding)**
   * 부트캠프 팀 프로젝트 성공의 최대 핵심은 **"실제 사용자의 피드백을 받아 개선하는 경험"**입니다.
   * 바이브코더 아이템은 **개발팀 4인 본인과 부트캠프 동료 전체가 즉시 데일리 유저**가 되므로, 외부 타겟 수급 없이 1일 차부터 매일 직접 써보며 개선점(Dogfooding)을 찾아낼 수 있습니다.

2. **AI 필수성 (AI-Native Core) 부합도 100%**
   * 단순 Wrapper 서비스가 아닌, **AST 코드 분석, Git Diff 파싱, LLM 기반 엣지케이스 테스트 코드 생성 및 Isolated Sandbox 실행**으로 이어지는 기술 스택은 AI 없이는 제품 자체가 성립하지 않습니다.

3. **4주 부트캠프 스코프의 완벽한 기술적 밀도**
   * 실버 타겟의 공공 인증서 연동 벽이나 강사 타겟의 저작권 DB 구축 이슈와 달리, **"Code AST -> LLM Architecture Validation -> Dynamic Mock/Test Generation -> Sandbox Runner"**로 이어지는 파이프라인은 4명의 개발자가 3~4주 동안 분업하여 기술적 역량을 최대치로 보여주기에 가장 적절한 과제 규모입니다.
