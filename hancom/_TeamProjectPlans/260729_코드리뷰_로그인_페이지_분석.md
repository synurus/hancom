# 로그인 페이지 HTML 코드 분석 — 발표 대본

**대상:** HTML 입문자 · **분량:** 약 5분 · **준비물:** 코드 화면 띄워두기

---

## 0. 여는 말 (약 20초)

안녕하세요. 오늘은 아주 짧은 HTML 코드 하나를 같이 뜯어보려고 합니다.

화면에 보이는 건 스무 줄 남짓한 로그인 페이지입니다. 짧지만 이 안에 웹 페이지가 갖춰야 할 기본기가 거의 다 들어 있어요. 위에서부터 한 줄씩 따라가 보겠습니다.

---

## 1. 문서의 뼈대 (약 50초)

맨 윗줄 `<!DOCTYPE html>`부터 보겠습니다. 이건 태그가 아니라 브라우저에게 보내는 선언입니다. "이 문서는 최신 HTML 규칙으로 읽어달라"는 뜻이에요. 이 한 줄이 빠지면 브라우저가 옛날 방식으로 해석해서 레이아웃이 어긋날 수 있습니다. 그래서 항상 첫 줄에 씁니다.

그다음 `<html lang="ko">`. 문서 전체를 감싸는 가장 바깥 상자입니다. 여기서 눈여겨볼 건 `lang="ko"`예요. 이 페이지가 한국어라고 알려주는 표시입니다. 화면상으로는 아무 변화가 없지만, 시각장애인이 쓰는 화면 낭독기가 이걸 보고 한국어 발음으로 읽어줍니다. 검색엔진도 참고하고요. 눈에 안 보이지만 중요한 정보입니다.

그 안은 크게 두 덩어리로 나뉩니다. `<head>`와 `<body>`입니다. head는 화면에 안 보이는 설정 구역, body는 실제로 눈에 보이는 내용입니다. 이 구분만 잡아두면 HTML 구조는 절반 이해한 겁니다.

---

## 2. head — 보이지 않는 설정 (약 60초)

head 안에는 세 줄이 있습니다.

첫째, `<meta charset="utf-8">`. 글자를 어떤 방식으로 저장할지 정하는 겁니다. UTF-8은 한글, 영어, 이모지까지 전부 표현할 수 있는 표준이에요. 이걸 빼먹으면 한글이 깨져서 외계어처럼 보이는 일이 생깁니다. 한글 페이지를 만든다면 사실상 필수입니다.

둘째, `<meta name="viewport" content="width=device-width, initial-scale=1">`. 조금 길지만 뜻은 간단합니다. "화면 너비를 기기 너비에 맞추고, 처음 확대 비율은 1로 하라." 이 줄이 없으면 휴대폰에서 열었을 때 데스크톱 화면을 억지로 축소한 것처럼 글씨가 깨알같이 작게 나옵니다. 모바일 대응의 시작점이라고 보시면 됩니다.

셋째, `<title>로그인</title>`. 브라우저 탭에 뜨는 이름이고, 즐겨찾기에 저장할 때의 제목이기도 합니다. 검색 결과에 나오는 파란 글씨도 이겁니다.

정리하면 head는 "글자 안 깨지게, 모바일에서 잘 보이게, 이름 붙이기" 세 가지를 하고 있습니다.

---

## 3. body — 실제로 보이는 부분 (약 90초)

이제 화면에 나타나는 부분입니다.

먼저 `<h1>로그인</h1>`. h1은 문서에서 가장 큰 제목입니다. 단순히 글씨를 크게 만드는 게 아니라 "이 페이지의 주제는 로그인이다"라는 의미를 담는 태그예요. 글씨 크기만 원한다면 CSS를 쓰면 되고, h1은 의미를 위해 씁니다.

다음은 `<form>` 태그입니다. 사용자가 입력한 값을 묶어서 서버로 보내는 상자라고 생각하시면 됩니다. 아이디와 비밀번호처럼 함께 전송돼야 하는 것들을 하나로 묶어주는 역할입니다.

form 안을 보면 label과 input이 짝을 이루고 있습니다. 여기가 오늘 발표의 핵심입니다.

```html
<label for="userId">아이디</label>
<input type="text" id="userId">
```

label의 `for` 값과 input의 `id` 값이 **userId로 똑같습니다.** 이건 우연이 아니라 둘을 연결하는 장치예요. 이렇게 연결해두면 "아이디"라는 글자를 클릭했을 때 커서가 입력칸으로 자동으로 이동합니다. 손가락으로 누르는 모바일에서 특히 편하죠. 그리고 화면 낭독기가 이 입력칸을 만났을 때 "아이디 입력칸"이라고 읽어줍니다. 연결이 없으면 그냥 "입력칸"이라고만 읽혀서 무엇을 넣어야 할지 알 수 없습니다.

두 번째 입력칸도 같은 구조인데 `type`만 다릅니다. 아이디는 `type="text"`, 비밀번호는 `type="password"`예요. password로 지정하면 입력한 글자가 점이나 별표로 가려집니다. 옆 사람이 화면을 봐도 비밀번호를 알 수 없게 되는 거죠. 참고로 이건 화면에서 가려주는 것뿐이고, 실제 전송을 안전하게 만드는 건 HTTPS의 역할입니다. 이 둘은 다른 문제입니다.

마지막으로 `<button type="submit">로그인</button>`. type이 submit이라 이 버튼을 누르면 form이 입력값을 모아 전송을 시도합니다. 사용자가 마우스 대신 엔터키를 눌러도 똑같이 동작하고요.

## 4. 이 코드에서 한 걸음 더 (약 50초)

이 코드는 구조가 깔끔하지만, 실제 서비스로 쓰려면 몇 가지가 더 필요합니다. 세 가지만 짚겠습니다.

첫째, form에 `action`과 `method`가 없습니다. 값을 어디로, 어떤 방식으로 보낼지 정해지지 않은 상태예요. 지금 버튼을 누르면 같은 페이지를 새로고침하는 것으로 끝납니다. 서버 주소를 넣어줘야 진짜 로그인이 됩니다.

둘째, input에 `name` 속성이 없습니다. id는 문서 안에서 요소를 가리키는 이름이고, 서버로 값을 보낼 때 쓰는 이름표는 `name`입니다. name이 없으면 값이 전송되지 않기 때문에, 실무에서는 id와 name을 함께 적어줍니다.

셋째, `required`를 넣으면 빈칸으로 제출하는 것을 브라우저가 막아주고, 비밀번호 칸에 `autocomplete="current-password"`를 넣으면 비밀번호 관리자가 제대로 인식합니다. 속성 한두 개로 사용성이 꽤 올라갑니다.

---

## 5. 맺음말 (약 20초)

정리하겠습니다. 이 스무 줄짜리 코드는 세 가지를 보여줍니다. 문서의 뼈대를 세우는 DOCTYPE과 html, 눈에 안 보이지만 필수인 head의 설정들, 그리고 label과 input을 짝지어 누구나 쓸 수 있게 만드는 form의 구조입니다.

특히 label과 input을 for와 id로 연결하는 습관, 이 하나만 가져가셔도 오늘 발표는 충분합니다. 감사합니다.

---

## 발표 팁

- 코드를 화면에 띄우고 설명하는 줄을 마우스나 커서로 짚어가며 진행하세요.
- 3번 항목의 label-input 연결은 브라우저에서 실제로 "아이디" 글자를 클릭해 커서가 옮겨가는 걸 보여주면 반응이 좋습니다.
- 시간이 부족하면 4번을 통째로 줄이고 "action과 name이 없어서 아직 전송은 안 됩니다" 한 문장으로 넘기세요.
- 시간이 남으면 개발자 도구(F12)로 요소를 직접 열어 보이면 1~2분을 자연스럽게 채울 수 있습니다.

## 예상 질문과 답변

**Q. id와 name은 뭐가 다른가요?**
id는 HTML 문서 안에서 이 요소를 가리키는 이름이고 CSS나 자바스크립트가 사용합니다. name은 서버로 값을 보낼 때 붙는 이름표입니다. 용도가 달라서 보통 둘 다 적습니다.

**Q. type="password"면 비밀번호가 안전한 건가요?**
아닙니다. 화면에 안 보이게 가려줄 뿐입니다. 전송 구간을 안전하게 만드는 건 HTTPS이고, 서버에 저장할 때는 암호화해서 보관해야 합니다.

**Q. label 없이 placeholder만 써도 되지 않나요?**
placeholder는 입력을 시작하면 사라집니다. 무엇을 적는 칸이었는지 알 수 없게 되고 화면 낭독기 지원도 불안정합니다. label을 쓰고 placeholder는 예시를 보여주는 보조 용도로 쓰는 게 좋습니다.
